# 太湖蓝藻数据清洗后续详细任务规划

> 规划版本：v1.0  
> 编制日期：2026-08-18  
> 工作边界：只负责数据接入、治理、质控、融合、反演校准数据准备、SQLite和实验数据交付；不开发页面、驾驶舱和数字孪生应用。  
> 第一原则：每一阶段必须有真实输入、可复跑命令、机器可读输出、质量门禁和运行清单；没有证据不标记完成。

## 1. 总目标与完成定义

最终交付不是“若干脚本”，而是一套可重复的数据产品流程：

```text
授权来源/公开来源
→ 原始数据不可变保存
→ 字段、时间、坐标、单位标准化
→ 异常检测、一致性校验、缺失处理
→ 小时/日重采样
→ 站点—气象—水文—遥感时空对齐
→ 特征与标签
→ 反演配对与校准
→ 批次级SQLite/CSV
→ 质量报告与模型实验交接
```

只有同时满足以下条件，数据清洗任务才可判定完成：

1. 至少遥感、地面水质、气象三类真实数据可重复接入；水文若暂缺必须有书面缺口与替代策略。
2. 叶绿素a、藻密度或水华面积至少一个目标具备连续时序；水温、TN、TP、风速、辐射等核心驱动达到约定频率。
3. 单次批次从接入到实验表可一条命令完成，所有输出共享同一`run_id`。
4. 原始值、清洗值、插补值、代理值和反演值可区分，转换规则和来源可追溯。
5. 重复、缺失、异常、时间、坐标、单位、时效性和授权均有量化报告。
6. 1—3天、7—15天、30—90天标签可用率达到模型团队确认的门槛。
7. SQLite为批次不可变交付，模型成员无需阅读清洗代码即可使用。

## 4. WP1：取得真实高频P0数据

### 目标

取得能真正支撑1—3天和7—15天预警的太湖地面数据，而不是继续依赖稀疏历史月度样本。

### 必须向项目方申请的数据

| 类别 | 必需字段 | 最低时间要求 | 空间要求 | 当前影响 |
|---|---|---|---|---|
| 藻情目标 | 叶绿素a、藻密度、水华面积至少一项 | 优选小时；最低日级连续 | 站点或网格有坐标 | 没有目标就不能训练/校准 |
| 水体状态 | 水温、DO、pH、浊度、透明度 | 小时级优先 | 与藻情同站或可配对 | 水温缺失直接削弱生长机理 |
| 营养盐 | TN、TP，最好含NH3-N、NO3-N、PO4-P | 日级优先；最低周级 | 同站或湖区代表站 | 当前月/季级频率无法短期推演 |
| 水动力 | 水位、流量、流速/流向 | 小时或日级 | 入湖河道、湖区、出湖口 | 影响输运与聚集，不可由气象完全替代 |
| 站点元数据 | 站点ID、名称、经纬度、水深、设备、有效期 | 变更时更新 | 全部站点 | 缺失会导致只能时间匹配 |

### 接入形式优先级

1. 项目方正式API及调用凭证；
2. 官方平台定时导出的CSV/XLSX/JSON；
3. 浮标/自动站数据库只读导出；
4. 人工采样历史表作为校准补充；
5. 公共网页抓取仅作最后备选，必须确认许可和稳定性。

### 交付与验收

- 连续至少7天的真实样例用于接入验收，随后补充至少一个完整蓝藻季；
- 每个文件保存SHA-256、来源、授权、下载时间和原始时区；
- 站点坐标覆盖率100%；
- 核心目标和驱动满足约定的频率门禁；
- 接口或文件格式变更可被契约测试发现。

### 无法取得时的降级方案

- 没有叶绿素a但有藻密度：用藻密度作为第一版目标，叶绿素反演只做接口演示；
- 没有藻密度但有叶绿素a：用叶绿素a作为目标，风险等级依据需单独标定；
- 只有水华面积：可做遥感面积预测，不声称生物量预测；
- 没有水温：短期使用气温/再分析水温代理并明确低置信度，但必须优先补采；
- 没有TN/TP高频：采用最近一次有效检测值加“距上次采样时长”特征，不做线性伪上采样；
- 三类目标全部没有：停止监督预测验收，只能交付无监督风险提示和数据流程演示。

### 规则分层

| 层级 | 检查 | 方法 | 返回 |
|---|---|---|---|
| L0结构 | 编码、文件损坏、必需列、类型 | schema与文件校验 | 拒绝或隔离文件 |
| L1基础 | 缺失、范围、枚举、单位、坐标 | 配置规则 | `quality_flags`、拒绝原因 |
| L2时间 | 重复、逆序、频率、时区、卡死 | 键约束、间隔和滚动窗口 | 重复表、时间问题表 |
| L3统计 | 尖峰、漂移、突变 | Hampel/稳健Z分数/变化率 | 异常分数和是否保留 |
| L4跨变量 | TN/TP关系、降水—流量、气温—水温 | 业务约束与软规则 | 一致性告警，不盲目删除 |
| L5跨来源 | 站点—遥感—气象一致性 | 时空邻近和差异阈值 | 匹配状态与置信度 |

### 建议验收指标

以下为项目建议阈值，需与企业导师确认后冻结：

- 故障注入异常召回率≥90%，误报率≤5%；
- 重复键清理后为0；
- 单位转换可追溯率100%；
- 插补必须输出方法、置信度和原值状态；
- 对人工遮蔽的短缺口比较线性、时间插值、KNN/迭代方法的MAE/RMSE；
- 长缺口和目标变量默认不自动插补，除非单独实验批准；
- 所有规则配置有版本，变更后自动重跑回归样本。

## 8. WP5：真实批次清洗、重采样与时空对齐

### 执行步骤

1. 原始数据按来源和日期不可变落盘；
2. 使用字段契约解析，生成标准长表；
3. 单位、时区、坐标和缺失标记标准化；
4. 执行QC并分成清洗、待插补、拒绝、问题四类；
5. 仅对通过策略的短缺口插补；
6. 自动站按小时/日重采样，低频人工采样保持原频率并携带“数据年龄”；
7. 使用站点主表进行空间匹配；
8. 气象、水文、遥感按明确时间窗和距离阈值对齐；
9. 生成因果滞后、滚动、累计和机理限制特征；
10. 运行P0覆盖门禁和多尺度标签检查。

### 推荐门禁

| 门禁 | 建议阈值 | 失败动作 |
|---|---|---|
| 必需目标存在 | 至少一类目标 | 停止监督数据集交付 |
| 高频站点中位间隔 | ≤6小时 | 标记不满足短期预警 |
| 高频站点最大关键缺口 | ≤24小时 | 不生成对应时段标签 |
| 站点坐标 | 100% | 禁止空间融合 |
| 单位未知 | 0条进入模型表 | 转入待确认区 |
| 重复主键 | 0 | 阻塞发布 |
| 代理/插补标记 | 100% | 阻塞发布 |
| 未来泄漏 | 0 | 阻塞发布 |

## 9. WP6：Sentinel-2反演与地面校准

### 执行链路

1. 通过Copernicus OAuth下载B02、B03、B04、B05、B06、B07、B08/B8A、B11/B12和SCL；
2. 保存产品ID、处理级别、时间、云量、校验和；
3. SCL云/阴影掩膜、太湖水体裁剪、不同分辨率重采样；
4. 计算NDCI、FAI、MCI/红边组合和水体掩膜；
5. 与地面叶绿素a或藻密度按时间差、距离和水域分区配对；
6. 按时间或湖区留出划分训练/验证/测试，避免同场景泄漏；
7. 比较线性/指数经验模型、随机森林/梯度提升及带物理限制方案；
8. 输出R²、RMSE、MAE、偏差、样本量、季节和湖区分层结果；
9. 生成像元产品、场景汇总和水华面积，并保留置信区间。

### 验收前提

- 至少有覆盖多个日期、多个湖区的同期地面样本；建议不少于30个有效配对，最终阈值由专家确认；
- 样本不足时只交付“算法接口和配对清单”，不报告泛化精度；
- 云量、配对时间差、空间距离和样本排除理由必须进入报告。
