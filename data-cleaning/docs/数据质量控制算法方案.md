# 太湖蓝藻数据质量控制算法方案

> 版本：v1.0.0  
> 适用范围：`data-cleaning/` 数据接入、清洗、插补、重采样、时空融合和模型实验输入。  
> 核心原则：原始数据不可覆盖；清洗值、插补值、代理值、反演值必须可区分；长缺口和蓝藻目标默认不自动造数。

## 1. 质量问题与处理边界

| 问题 | 检测方式 | 处理方式 | 是否进入模型表 |
|---|---|---|---|
| 文件/字段错误 | 文件解析、必需列、类型 | 文件隔离并记录原因 | 否 |
| 缺失值 | 空值、空字符串、源缺测码 | 进入待插补表；仅短缺口进入显式插补 | 仅通过插补门禁后 |
| 重复记录 | 来源+站点/场景+时间+变量复合键 | 保留原始记录，重复记录拒绝模型表 | 否 |
| 物理范围异常 | 配置硬范围 | 加问题标志并拒绝 | 否 |
| 时间/坐标异常 | ISO时间、时区、经纬度范围 | 隔离并回传来源 | 否 |
| 单位不一致 | 单位表和转换规则 | 可转换则保留转换链，不可转换则拒绝 | 视结果 |
| 尖峰/突变 | Hampel、MAD、IQR和变化率 | 先标记，人工/跨源复核后决定 | 默认保留并标记 |
| 跨变量矛盾 | 水温—气温、TN—TP、降雨—流量等软规则 | 告警，不直接删除 | 视复核 |
| 过期/低频 | 中位间隔、最大间隔、最新时间 | 覆盖门禁失败，不伪造高频 | 不满足短期门禁 |

## 2. 规则分层

1. L0结构层：文件可读、编码、必需列和类型。
2. L1有效性层：范围、枚举、单位、时间和坐标。
3. L2一致性层：重复键、时间顺序、站点主表和单位转换。
4. L3统计层：稳健离群、突变、漂移、卡死和长时间常值。
5. L4跨源层：站点—气象—遥感—水文的时间差、空间距离和响应关系。
6. L5业务门禁层：目标、驱动、频率、新鲜度和未来标签可用性。

## 3. 当前实际加载的配置

规则文件为`config/qc_rules.yml`，由`pipeline/qc.py`加载。当前硬范围保持跨来源的安全上限：气温、风速、风向、降水、短波辐射、云量；这些范围与变量字典使用同一单位，但不等同于单站点仪器量程。重复键、缺失值、风向360°归一化和拒绝代码均由配置控制。

水温、TN、TP、叶绿素a、藻密度和水华面积目前列为“建议范围/业务告警”，不在没有站点校准和授权数据前直接硬拒绝。这样可避免把历史来源的单位或检测上限误当作通用物理边界。

## 4. 缺失值策略

- 目标变量叶绿素a、藻密度、水华面积：默认不自动插补；缺失只进入待处理表。
- 普通驱动变量：仅允许显式配置的短缺口线性时间插值，必须输出`is_imputed`、`imputation_method`、`imputation_confidence`和`value_origin`。
- 长缺口：保留缺失和数据年龄，不做线性跨季节填充。
- 代理数据：必须标记`value_origin=proxy`或`forecast_proxy`，不得与实测值混写。
- 对重采样：低频数据不得通过上采样伪造小时观测，应保留原始频率和距上次观测时长。

## 5. 异常检测算法选择

### 5.1 规则和稳健统计组合

- 范围规则：适合风速、降水、云量等边界稳定字段；越界进入拒绝或告警。
- Hampel/MAD：适合小时序列尖峰，较普通均值标准差更不受极端值影响。
- IQR：适合历史批次分布检查，不单独作为删除依据。
- 变化率和卡死：检查相邻值突变、长时间完全相同、时间戳重复和时间倒退。
- 跨变量软约束：用于复核，不直接删除，避免把极端天气当异常。

### 5.2 不同数据源的规则

| 数据源 | 首选规则 | 重要限制 |
|---|---|---|
| 自动站/浮标 | 范围+频率+卡死+Hampel | 设备检修期间应有停机标记 |
| 人工采样 | 单位、范围、站点和采样时间 | 低频不能上采样 |
| 气象 | 范围+时间完整性+降水累计检查 | 再分析/预报必须标注来源 |
| 遥感 | SCL掩膜、云量、有效像元比例、反射率范围 | 不对无效像元插补 |
| 水文 | 水位/流量范围、时间连续性、水量平衡软约束 | 基准面必须确认 |

## 6. 故障注入与验收

现有`pipeline/fault_injection.py`已覆盖缺失、越界、重复和无效时间四类故障，第一版fixture召回率目标为100%。生产验收建议：异常召回率≥90%、误报率≤5%；插补使用人工遮蔽样本比较线性插值、KNN/迭代等方法的MAE/RMSE，并按变量、站点、季节分层。

## 7. 输出与审计字段

每条记录必须保留：原始文件、源行号、原值、清洗值、标准单位、转换规则、值来源、质量标志、插补方法、插补置信度、观测时间、站点/场景和批次ID。质量报告至少包含记录数、缺失率、重复数、拒绝数、问题数、频率状态、时效状态和代理/插补计数。

## 8. 已知限制与下一步

- 当前硬规则尚未覆盖所有93字段的站点专属检测上限；需要项目方提供仪器量程、检出限和单位说明后再升级。
- 当前没有真实高频水质数据，异常召回和插补误差仍是fixture级证据，不能当作业务效果。
- 下一步用真实授权批次运行故障注入、分源缺失率和7日稳定性测试，并冻结QC规则v1.1。
