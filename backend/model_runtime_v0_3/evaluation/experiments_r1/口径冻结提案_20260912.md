## 一、现行 uplift 定义调研结论（gate.py，唯一来源）

生成机制（`gate.py::build_gate_table`，扫描 `runs/*/`）：

1. 每个 run 目录读三件产物：`run_config.json`、`selection_manifest.json`、`test_metrics_by_family.json`。三件都来自 `training_real.train_run_real` 的同一次训练：**全部候选族在同一冻结评估帧（同一切分的 test 段）上各评估一次并落盘**，因此比较本身是同帧的。
2. `fusion_family` = validation 选中的 `selected_family`（若它属于融合族 mechanism_feature/residual/constrained_blend），否则取 validation 主指标最优的融合族；`single_family`（best_single）= validation 主指标最优的**单一数据驱动族**（random_forest / xgboost 较优者）。选族时 macro_f1 缺失回退 accuracy，平 tie 取注册序首。
3. uplift 公式（与本次冻结提案 F2 完全一致，予以沿用冻结）：
   - min 方向（brier_score / mae / log1p_mae）：`uplift = (best_single − fusion) / best_single`，下降为正提升；
   - max 方向（macro_f1）：`uplift = (fusion − best_single) / best_single`，上升为正提升。
4. 判定：`uplift ≥ 0.10` 且 `n_test ≥ 15` → PASS，否则 FAIL；`n_test < 15` → NA（reason=test_n_below_minimum_15）；基线值为 0 时 uplift 记 None → FAIL（即"不机械算百分比"的现行实现）。
5. 总门禁为内部规则"PASS 比较项 ≥90%"，与赛题原文"整体预报精度较单一模型显著提升"不是同一句话，该差距已在台账说明。

**结论：现行 uplift 的比较对象 = 同 run 同帧下 validation 选出的最优单一 AI 族；公式与方向性没有问题，问题出在"被比较的实验本身"（见第三节诊断）。**

## 三、结构性诊断（T3b 修复输入，均已用当前代码+产物复现/验证）

1. **机理支路全线退化（最关键）**：42/42 个 run 中 mechanism 族与 simple_baseline（训练均值/先验常数）在同帧指标**精确同值**（validation 与 test 皆然）——机理支路输出常数，三类融合族融合的都是常数。已复现的退化路径：
   - T3/T4：任务级目标同源剔除把 `wq_phyto_biomass` 置全 NaN → `_fit_mechanism` 的行有效性门要求设计矩阵 17 列全部有限 → 全部行被判无效（复现 valid=0/576）→ 常数回退；
   - 监督面板机理列本身信息量缺失：`mech_net_growth_rate_d` 全 0（T1/T5 面板），T5 面板 `mech_light_factor` 全 0，T3/T4 面板 `met_air_temperature_c`、`met_shortwave_radiation_wm2` 全 NaN→0；
   - T1/T5 在当前代码+当前数据下机理族可以拟合（产物由更早代码/数据状态生成），即重训本身就能消除一部分退化，但面板机理列缺信息仍需 T1/T3b 修复。
2. **T6 序数评估 bug**：`train_run_real` 评估循环对 `actual` 统一 `pd.to_numeric(errors="coerce")`，序数字符串标签（none/low/medium/high）全部变 NaN；`ordinal_metrics` 把 NaN 当类 'nan'，与预测类永不相交 → macro_f1=accuracy=0。validation 同路径 → 全族 0 分平 tie → simple_baseline 被选中。**修复方向：序数分支保留原始字符串 actual**（runner 的 retrain 路径已按此实现并用合成样例验证：同路径 RF macro_f1=0.919，而现网为 0.0）。
3. **validation 选族失真**：T1-bloom frozen validation 全阴性（常数 0 即 Brier=0），全族平 tie → 注册序首的 random_forest 当选；选族证据在单类 validation 上无效。须在选族时校验 validation 双类/足够阳性，否则行级标注 weak_selection_basis。
4. **同源复用**：8 个 (task, variant, month_offset=0, protocol) 组的 h1/3/7/15 全部是同一实验的多行引用（runner 自动甄别见 dryrun JSON 的 duplicate_experiment_groups；T3/T4/T5-cv 组仅差 1e-17 级浮点抖动）。T6-probability 与 T1-bloom 是同一实验跨任务复制。
5. **两套评估窗口并存**：frozen_split 行的 test=2024-09..2026-08（真冻结段）；cv 协议行的"test"是训练期内时间块（2017-08..2020-11 等）。两者都真实、都不许混用，但对外表述必须区分（见 F4）。
6. **弱事件支持**：T1/T6-probability frozen test n=40、阳性 1/40。

## 四、冻结条款（F1~F6，主控确认后生效）

### F1 主指标集合（不得混写）

| 任务 | 主指标 | 方向 | 说明 |
| --- | --- | --- | --- |
| T1 binary / T6 probability | brier_score | min | 概率任务；R²/准确率不得替代 |
| T3 density | log1p_mae | min | 对数空间 MAE（秩代理目标良定义） |
| T4 biomass / T5 chla | mae | min | 原量纲 MAE |
| T6 risk_level（ordinal） | macro_f1 | max | 测试段真实类别 ≥2 时才可判 PASS；单类段按 F5 记 INDETERMINATE 并附 accuracy 参考 |

- R² 只作拟合诊断披露，不进任何提升判定；R² 为负时如实写"劣于均值基线"。
- **每一条百分比提升声明必须绑定指标名**（正确示例："T3 log1p_MAE 相对最优单一 AI 下降 19.3%"；禁止："精度提升 19.3%"）。

### F2 提升公式（沿用 gate.py 现行式，予以冻结）

- min 方向：`uplift = (baseline_metric − model_metric) / baseline_metric`（下降为正）；
- max 方向：`uplift = (model_metric − baseline_metric) / baseline_metric`（上升为正）；
- PASS 判定：`uplift ≥ 0.10` 且 `n_test ≥ 15` 且测试段类别支持满足 F4；
- 冻结后实验不许换口径；如需并报绝对差（`baseline − model`，带原单位）必须与百分比并列披露，不得相互替代或挑选有利者。

### F3 比较基线选择原则

1. **主基线（10% 判定用）**：同 run、同切分、同 seed、同一冻结评估帧上，validation 主指标最优的单一数据驱动族（random_forest/xgboost 较优者；平 tie 取注册序首，规则与 gate.py 一致并冻结）。对齐赛题原文"较单一数据驱动模型提升不低于 10%"。
2. **禁止基线挑选**：不得在测试集上挑对融合最有利的族当基线；选族依据（validation 指标）须随行落盘。
3. **对照披露（不参与 10% 判定，防"复述 persistence/climatology"）**：simple_baseline、climatology_global、persistence（如注册）在同帧的指标与 uplift 必须同表披露。融合模型若不敌季节基线，即使对 AI 基线 ≥10%，对外也不得表述为"机理融合增益"，须标注"未越过季节基线"。
4. **机理-only（mechanism）作为消融臂**：融合 uplift 必须 > 机理-only 单独水平，才能把增益归因于"机理+AI 融合"；机理退化运行（F5-6）的融合增益一律归为噪声。
5. validation 单类/全阴导致选族平 tie 时，行标注 `weak_selection_basis`，该行 PASS 不得作为唯一 10% 证据。

### F4 测试窗口与切分原则

1. **同切分铁律**：任何比较行的 fusion 与 baseline 必须来自同一 run（同一切分、同一评估帧、同 seed、同特征契约）；跨 run/跨协议数值禁止相减。
2. **窗口披露**：每行必须带 test 月份区间、n_test、training_protocol、（binary/probability）阳性数。
3. **权威窗口分级**：
   - 冻结测试段（≥2024-01）有标签的任务（T1/T6-probability 等）：10% 声明以冻结段为准；
   - 标签全在训练期的任务（T3/T4/T5/T6-risk_level 现状）：以补训协议 `train_internal_time_block_cv_v1`（60/20/20 月份时序块，无前视）的留出块为权威窗口，行与页面必须写明"训练期内时间分块留出段"，**禁止表述为"2024+ 测试集"**；
   - T1 时间配对审计交付后：若能构造真实日尺度目标，短时效改用真实 T+N 配对与事件级切分重训重评。
4. **短时效同源披露**：1/3/7/15 天映射同一 month_offset=0 实验的，按**一行独立实验**计；多时效展示须注明"同一月度实验的不同时效披露"，不得计为四份独立证据；四个短时效 density 同值行必须变成真实独立实验或如实标注（看板 T3b 原文）。
5. **事件级切分**：同一水华事件不得跨 train/test（等 T1 审计结论落地后作为切分约束执行）；跨站点泛化以 station_cv 留一分区协议作补充披露。
6. **最低样本量与事件支持**：n_test ≥ 15 维持；binary/probability 行披露阳性数，阳性 <5 的 PASS 行加 `weak_event_support` 标记，不得作为唯一 10% 证据。

### F5 不足 10% 与特殊情形的如实报告

| 情形 | 行状态（提案） | 报告要求 |
| --- | --- | --- |
| 0 ≤ uplift < 0.10 | `FAIL_below_10pct` | 写 uplift 数值 + gap（距 10% 还差多少百分点）；禁止"接近/趋势向好"表述 |
| uplift < 0 | `FAIL_worse_than_baseline` | 如实写"劣于基线"并给差值 |
| 基线 = 0 / 指标不可算（全零 macro_f1、单类段） | `INDETERMINATE_baseline_zero_or_not_computable` | 不机械算百分比；披露绝对差与方向；不计入 PASS 分母、不得标 PASS；改判须主控裁定并留台账记录 |
| n_test < 15 | `NA`（现行规则） | 披露 na_reason；对应赛题必需能力的在验收总表记未完成 |
| 族训练/预测失败 | `ERROR_family_failed` | 不得静默缺席，披露错误摘要 |
| 机理退化（mechanism 与 simple_baseline 同帧指标精确同值，或机理预测唯一值数 ≤1） | 行带 `mechanism_degenerate` 标记 | 该 run 全部融合 uplift 不得解释为机理增益 |

## 五、与 runner 的对应关系

`ablation_runner.py` 已按本口径实现并 dry-run 跑通：

- offline 模式 = 对既有 runs 的同帧复算 + gate 交叉核对（84/84 复现）+ 同源复用甄别 + 机理退化甄别；

- 序数评估按 F4 修复口径实现（字符串标签直通），与现行 gate 路径的差异已在 selftest 中量化证明。
