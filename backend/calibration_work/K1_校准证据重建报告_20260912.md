## 4. OOF 重建自证结果（怎么证明没冒充）

重建**直接 import 训练代码真实实现**（`target_builder` / `data_real` / `training_real` / `cli_real_cv`）复刻同一套切分与折函数，不是另写一套等价逻辑。判定"OOF 没有用见过该样本的模型冒充"，靠以下机器可验证锚点（全部见 `reconcile_*.json` 的 `checks`，T+1/T+90 均 `all_checks_pass=true`）：

| 自证锚点 | T+1 | T+90 |
| --- | --- | --- |
| 重放 `train_features` 指纹 == 原 run `selection_manifest.feature_sha256` | 是（`22d8947f…`） | 是（`14171006…`） |
| 重放测试段逐行预测 == 原 `test_predictions.csv`（最大绝对差） | 7.1e-15 | 7.1e-15 |
| 重放 validation MAE == `selection_manifest.validation_value` | 是 | 是 |
| OOF 行全部落在 late 折（`month ≥ cut`） | 是 | 是 |
| early 拟合块月份全部 `< cut`，且与 late 无 row_id 交叠 | 是 | 是 |
| 折边界严格时间递增（`max(fit_month) < min(late_month)`） | 是 | 是 |
| OOF 残差向量 == 原 `_fit_oof_residuals` 返回值（1e-9 容差） | 是（实测 7.1e-15） | 是（实测 ~7e-15，逐次运行在 1e-14 量级波动） |
| OOF row_id ⊆ CV train，且与 validation row_id 不相交 | 是 | 是 |
| validation row_id == CV validation 块（集合完全相等） | 是 | 是 |
| 残差池 row_id 与 CV test 块无交集 | 是 | 是 |
| 预处理器中位数 == bundle 内预处理器 | 是 | 是 |

说明：
1. **"未见性"证明方式**：OOF 预测由 `factories[selected](early, None)` 产出，该折模型只吃 early 块；脚本断言 OOF 行的时间全部 ≥ cut、拟合块最大月 < cut、两集合 row_id 无交。因为部署模型本身是"全 train 拟合"的模型，**绝不能**用它预测 train 行来当 OOF；本重放特意只复用了原训练代码里那个 early-only 折模型。
2. **逐位相等不可达的诚实说明**：RF/HistGB 在 `n_jobs=4` 下重复拟合有 ~1e-14 级浮点差异（非结合求和）。实测两次调用原函数的差同为 ~7e-15，故残差向量/分位数采用 1e-12~1e-9 容差判定，并记录实测最大差。
3. **逐行残差可比对的边界（重要且如实）**：模型文件**从未保存旧残差池的逐行内容**（只存了 P05/P95 标量）。因此"逐行样本身份 vs 旧分位数"不可能与"旧逐行记录"直接对账——旧记录不存在。我们能做的是：用与原训练逐步一致（特征指纹、测试预测、族选择指标、分位数全部逐项相等）来证明重放管线等价，从而由重放池推出的逐行身份即为原池身份。这正是台账 L-cal-10 的实质。

## 7. 关键发现：训练代码版本漂移（重放必须用训练当时的代码）

首次用**工作区 HEAD 代码**重放时，测试段 132/132、117/117 行 `actual` 与模型记录**全部不一致**（预测最大差 26.5 / 14.1），`feature_sha256` 不匹配，分位数自然对不上。

根因：部署模型产生于 **2026-09-11 13:31-13:32**；`target_builder.py` 在 **2026-09-12（commit `d92c421`，"T3b"）** 新增了 `_normalize_chla_units()`（把 water_quality 里 chla 的 mg/L 行 ×1000 统一到 μg/L，L-data-05），README 注释亦载明会改变标签量纲。工作区当前代码与该 commit 之后一致，因此**用现码重放无法复现旧模型**。

处置：本重建从 git 只读导出 commit `73be6e7`（2026-09-11 23:37，晚于模型 mtime 09-11 13:31 约 10 小时且 `feature_sha256` 复核证明其间 `modeling_real` 未再变）的 `modeling_real` 包到 `_replay_pkg/`（由 `export_replay_package.py` 可复跑生成），用其重放后 `feature_sha256`、测试预测、族选择指标、分位数全部精确复现。**这本身是一条重要证据**：部署模型与其对应的"当前代码"并非同一版本，任何用现码做的区间重演都会系统性错位——建议入台账。

（若需严格到 commit 级，可再核对模型文件 mtime 2026-09-11 13:31 与 `73be6e7` 提交时刻之间的 `modeling_real` 变更；本轮以 `feature_sha256` 与测试预测逐行相等作为等价性证明。）

## 8. T+90（mo3）协议核验结论

T+90 与 T+1 **同为** `train_internal_time_block_cv_v1`（训练期内时间分块，非冻结划分），但**切分键与窗口不同**：

| 项 | T+1（mo0） | T+90（mo3） |
| --- | --- | --- |
| split_key | `month`（输入月） | `target_month`（目标月，防前视） |
| train_max_month | 2014-11 | 2014-05 |
| validation_max_month | 2018-05 | 2017-08 |
| cv_test 起点 | 2018-08 | 2017-11 |
| CV 三块行数 | train 360 / val 126 / test 132 | train 333 / val 117 / test 117 |
| 标签来源 | 混合（校准池 100% 代理） | 全代理 `chla_station_proxy_v1`（567 行） |
| 与冻结段关系 | 冻结 test≥2024-01；CV 测试段是**训练期内**更早月份，二者不同口径 | 同左 |

结论：
- T+90 **能重建**（本轮已重建，五重对账全过），且已如实保存 OOF/validation 分池。
- 双窗口并存属实：mo0 与 mo3 的窗口边界不同（因切分键不同：输入月 vs 目标月）；**两者都不是冻结 2024+ 测试段**，其"测试覆盖率"均在训练期内的较晚留出块上核算。
- 校准残差池来源口径：T+90 全部为代理标签，无实测标签参与校准——其区间语义是"代理标签口径下的 conformal 区间"，对外应继续按 `proxy_derived` 披露。
- 按 §5 红线，本轮**不**用测试残差重定 T+90 分位数；仅为后续 K2 提供分池证据。
