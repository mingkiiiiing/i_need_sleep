## 4. month_offset=0 时间配对审计（L-vfy-03）

### 4.1 事实

1. 冻结映射 `contracts_real.HORIZON_MONTH_MAP_V3 = {1:0, 3:0, 7:0, 15:0, 30:1, 60:2, 90:3}`（`backend/model_runtime_v0_3/code/modeling_real/contracts_real.py` L184）。
2. 用当前代码重算 `build_supervised_table`（T1-bloom / T5-chla / T6-probability，mo=0）：**`target_month == month` 全部 100% 成立**（T1 657/657）。即输入特征与目标标签取自**同一个自然月**，是"当月诊断"而非"未来预测"。
3. 同源复用复核（对应台账 A 组观察 1）：`gate_table.json` 中 T1 binary h1/3/7/15 四行的 `run_id` 全部为 `T1-bloom-0m-s20260907`，fusion_value 同为 0.025050340541213956、best_single_value 同为 0.025069711113573562 → uplift 0.00077 是**同一实验在四个"时效"上的复制**；T6 probability 与 T1 同为 bloom 家族 mo=0，同一监督表同一 run（跨任务复制）。T3a dryrun `ablation_offline_20260912.json` 的 `duplicate_experiment_groups` 已列出 T1/T3/T4 三组，与本审计独立复算一致。
4. h90 uplift=-2.78（T1/T6p，n=28）与 h30/h60（n=5，NA）同理同源于 mo=3/mo=1 的补训 run，非独立日尺度证据。

### 4.2 能否用现有数据构造"未来 N 天"真实配对

| 目标源 | 覆盖 | 粒度 | 可行性 |
| --- | --- | --- | --- |
| CLMS LWQ 10-day（chla_mean/uncertainty/fcb_prob） | 2024-09..2026-08，24 个月，全湖单空间单元（TAIHU_LAKE） | 旬 | **修复 §5 的三列同值缺陷后**可构造旬尺度（约 70 旬）前瞻目标；可支撑 7-15 天近似（1-2 旬） |
| MEE 实时（silver/mee_realtime/observations.parquet） | **仅 2026-09-04..09-12 共 8 天**，79 站半小时级，含 chlorophyll_a、cyanobacteria_density | 半小时 | 是唯一真实日尺度藻类目标；跨度不足以回测任何时效；需持续积累 ≥3~6 个月才能形成 T+1/T+3 最小回测集 |
| MODIS-Aqua chla_retrieval | 2003..2026，331 景 | 逐景（非固定周期） | 可作湖面月均标签（现有用途），云覆盖/质量行需按 valid/review 口径披露 |
| 地面常规水质（THQBCA-V2） | 2005-02..2020-11，季度 | 月聚合 | 无 chla；无法做未来目标 |
| backend/sample-data 模拟数据 | 6 行 | — | value_origin=simulated，禁止作为目标 |

### 4.3 结论与缺口清单

- **结论**：1/3/7/15 天时效无法用现有历史数据构造可信的"未来 N 天"回测集（历史期无日/旬尺度藻类目标）。30/60/90 天的月粒度配对真实成立，应作为多时效证据的基线口径；台账 L-vfy-03 的"不构成四份独立日尺度证据"判断**成立并加严**：四行实为同一 run 的复制。
- **缺口清单（缺数据如实列阻断）**：
  1. 历史日/旬尺度叶绿素或藻密度目标（1-15 天时效必需）——缺失；
  2. CLMS 10-day 的多站点/分区提取（当前只有全湖单单元）——缺失；
  3. MEE 实时数据时间跨度（8 天）——需等待积累；
  4. CLMS 装配层三列同值修复（否则旬尺度目标不可信）——见 §5。

## 5. 机理列数据溯源（L-diag-01 核对）

### 5.1 wq_phyto_biomass：逐级证据链（详见 `audits_out/mechanism_provenance_chain.csv`）

| 层级 | 文件 | 结果 |
| --- | --- | --- |
| 0 原始数据 | `01_当前主原始数据/taihu_thqbca_zenodo/extracted/THQBCA-V2/1.WaterQuality/1WaterQuality.xlsx`（water_quality.parquet `source_file` 字段记录） | 存在 |
| 1 清洗层 | `data-cleaning/storage/final_cleaned/TAIHU_CLEAN_FINAL_V1_20260831/tables/water_quality.parquet` | **576 行 phyto_biomass，全 valid、全 ground_truth、单位 mg/L、值域 0.001225~76.9029、2005-02..2020-11、9 个分区站** |
| 2 装配层 | `tables/model_dataset.parquet` | wq_phyto_biomass 非空 576/914，nunique 569 |
| 3 监督底表 | `backend/model_runtime_v0_3/supervised/features_base.parquet` | 非空 576/914 |
| 4 任务监督表（重算） | T1-bloom-0m / T5-chla-0m | 列在，576/657、576/618 非空；机理设计矩阵训练帧 586/586 行有效，**不会**触发常数回退 |
| 4 任务监督表（重算） | T3-density-0m / T4-biomass-0m | **列被契约剔除不存在**（`TARGET_SOURCE_FEATURE_EXCLUSIONS` 防同月泄漏）→ `_mechanism_design` 对缺席列置整列 NaN → 17 列有效性门 0/576 行有效 → `_fit_mechanism` 必然常数回退 |

**判定（L-diag-01 精化）**："wq_phyto_biomass 全 NaN"不是源头数据缺失、不是装配丢失——五个层级都有真实数据。全 NaN 只发生在 T3/T4 任务监督表层，由两段代码的交互造成：

- `contracts_real.TARGET_SOURCE_FEATURE_EXCLUSIONS = {"biomass": ("wq_phyto_biomass",), "density": ("wq_phyto_biomass",)}`（防同月泄漏，正确）；
- `training_real.MECH_DESIGN_BASE` 硬编码 17 列包含 `wq_phyto_biomass`，`_mechanism_design` 对帧中缺席的列填 `np.nan`（`training_real.py` L333-347），`_fit_mechanism` 要求 17 列逐行全有效（`valid = np.isfinite(x).all(axis=1)`，`valid.sum() < 10` 即常数回退）。

→ **结论：L-diag-01 的机理退化（至少 T3/T4 支路）是软件 bug（剔除列与设计矩阵冲突），修复方向是让机理设计矩阵在任务级剔除列时收缩列集，而不是找数据。** 数据层不需要任何新增数据即可修复该退化。

### 5.2 mech_net_growth_rate_d 全 NaN / 恒 0

- 监督底表 914 行**全 NaN**。根因：`_mechanism_columns` 计算 `net = 0.9·f_T·f_I·f_N − 0.16`，三个因子的观测来源是**互不相交的站点集合**——温度非空 374 行（NASA_POWER 网格 242 + IN_SITU 实测 41 等）、光照非空 242 行（仅 NASA_POWER）、营养盐非空 576 行（仅 TAIHU 分区站），三者交集 **0 行**（审计实测 `temp_light_tp_intersection_rows=0`）。月度宽表结构上不可能有一行三者齐全。
- 训练时 `RealPreprocessor` 对全 NaN 列取 `median=0.0` → **训练特征 mech_net_growth_rate_d 恒 0**（审计实测 T5/T1 训练帧该列常数 0.0）。这就是"训练与面板中 net_growth 全 0"的机制。
- 运行时面板（`backend/app/algorithm_models.py _mechanism_drivers`，L2131-2277）是独立实现：按"本站 MEE 实测→ERA5 网格→气温回退"逐因子取值，输入齐全时 net 可非 0——训练与展示因此**用了不同完备度的同一公式**（面板可算、训练恒 0）。

### 5.3 mech_light_factor

- 底表仅 242/914 行非空（NASA_POWER 行，值域 0.1509~1.0）。TAIHU 分区站行全 NaN。
- 训练帧（T1/T5 mo0 的 train split）内光照列**全 NaN → 中位数插补为 0.0 → 训练帧 mech_light_factor 恒 0**（同时 met_air_temperature_c、met_shortwave_radiation_wm2、log1p_wq_chla 也恒 0，共 5 个常数列）——这就是台账"面板/训练 mech_light_factor 全 0"的确切出处。
- 运行时面板取 NASA_POWER 网格月值（2.7~254.9 W/m²），`clip(light/18)` 使光照因子常年饱和为 1.0（代码注释自认，非"光照理想"）。机理因子在训练侧退化成"温度×营养盐"二元函数。

### 5.4 runs 产物与当前代码不可复现对齐

用当前代码重跑 T5-chla-0m 的 mechanism 候选：设计矩阵 586 行全有效、HistGB 正常拟合、validation mae=1.196（预测 2 个值）；而 `runs/T5-chla-1d-0m/selection_manifest.json` 落盘 mechanism mae=3.978135 与 simple_baseline **精确同值**（常数回退特征）。说明 runs/ 产物由旧版代码产出，当前代码无法复现落盘指标 → 冻结评估前必须统一版本全量重跑（与台账 L-diag-01"retrain 冒烟证明当前代码重训仍退化"对照，说明退化路径有多条：T3/T4 是剔除列 bug，T5/T1 的落盘版本另有历史原因）。

### 5.5 标签层的两个上游数据缺陷（本次新发现，直接影响 T1/T5/T6 标签真实性）

**缺陷 A：CLMS 三个语义列在装配层 100% 同值。**
`model_dataset.parquet` 的 `rs_clms_lwq_300m_10daily_chla_mean`、`..._chla_uncertainty`、`..._fcb_prob` 三列在 40 个非空行上**逐行完全相同**（值域 89.35~188.12 ≈ fcb_prob×1e4 缩放【2026-09-12 交叉审查注：该缩放推断与下文清洗层 fcb_prob 0~0.0094（×1e4≤94<188.12）及行 881 实测 95.99 vs 81.79 不自洽，降级为待复核；核心结论"三列同值、chla 语义缺失、根因阻断"不受影响】）。而同一发布的清洗层长表 `taihu_clean_final_long.parquet` / `remote_sensing.parquet` 中三者语义正常（chla_mean 3.5~10.5 μg/L、uncertainty 13.1~16.3、fcb_prob 0~0.0094）。后果：
- 78 列特征契约中 `chla_mean` 及其 3 个 lag/roll 列的实际语义是 FCB 概率，chla 遥测信息在训练特征中**不存在**；
- T2 coverage 标签 `label_coverage_fcb_prob = fcb/1e4` 建立在同值列上（碰巧自洽但无独立信息）；
- bloom 阳性判定中 FCB≥0.5 支路恒不触发（40 行全部 ≈0.009）。
**阻断**：中间清洗层 `data-cleaning/storage/cleaned/*.csv`（装配脚本 `build_model_dataset.py` 的直接输入）已不在仓库，无法定位写坏点（上游 csv 串列还是 pivot 冲突），需重建管道复现。

**缺陷 B：野外 chla 单位混用（mg/L 与 ug/L 重复入库）。**
`water_quality.parquet` 中 chla 83 行 = taihu_field_samples **mg/L 41 行（0.00113~0.01803）+ ug/L 41 行（1.13~18.03）**——数值严格同值异单位成对（38 对完全匹配）+ taihu_water_quality 1 行 0.03（mg/L）。`load_label_wide` 用 `aggfunc="mean"` 对同 (station,month) 的两种单位行求均值 → 野外月标签被混合单位污染（约等于真实 μg/L 值的一半量级）。连锁效应：
- chla 代理锚点（2020-12 航次均值）被拉低 → `chla_station_proxy_v1` 全部代理标签系统性偏低（代理值集中在 1~7 μg/L，与太湖真实夏季 20~50 μg/L 量级不符）；
- bloom 阈值 20 μg/L 下代理阳性仅 22/914 行（全部为 5 月/8 月季节峰）；野外实测无论按哪种单位均无 ≥20 μg/L 阳性（max 18.03 μg/L）；
- T1/T6p 阳性极度稀缺（test 1/40）的根因在此，属**数据缺陷**而非模型能力问题。
（装配脚本 `build_model_dataset.py` L81-83 亦直接把 `field_samples_cleaned` 的 `chla_mg_l` 列当 target_chla 使用，印证单位口径从未归一。）

## 6. 水华事件切分审计（L-vfy-04）

- 月粒度监督表（T1-bloom mo0，657 行）中共识别 **23 个连续阳性事件段**，全部为孤立单月（2005-05..2019-08 的 5 月/8 月季节峰，station 分布：TAIHU_ZS 11、TAIHU_ML 5、TAIHU_WT 5、TAIHU_GH 1、TAIHU_WHOLE 2），加 1 个 test 事件（2024-12 TAIHU_WHOLE，CLMS bloom_label）。
- **跨集合泄漏：0 个事件跨 train/validation/test**（`event_split_events.csv`）。冻结切分（train≤2021-12 / val 2022-2023 / test≥2024-01）使 train 与 test 之间有 ≥32 个月间隙，validation 31 行全阴性。
- 但三条保留意见：
  1. 23 个训练期"事件"全部由 `chla_station_proxy_v1` 代理 chla 派生（§5.5 缺陷 B 拉低阈值通过率），**事件真实性受代理标签质量约束**；真实观测事件只有 2024-12 一个月（CLMS bloom_label）。
  2. 月粒度无法识别旬级事件拆分；若未来用 CLMS 10-day 构造旬尺度标签，必须重做事件级切分。
  3. "T1-bloom-1d-0m 阳性 1/40 事件泛化弱"（L-vfy-04）的定性成立，但根因排序应为：单位混用→代理锚点拉低→阳性稀缺（数据缺陷）优先于切分方案。
- **事件级切分建议**：event_id = (station_id, 连续阳性旬/月段)，划分时**整段分配**到 train/validation/test；事件前后各 1 个时间步作为缓冲不进入任何评估集；先修复 §5.5 两缺陷，用 CLMS bloom_label/FCB 旬场（而非代理 chla）定义事件，再重切分。
