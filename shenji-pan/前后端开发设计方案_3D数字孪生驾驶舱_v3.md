## 0. 最终交付结论

系统不是一张“好看的大屏”，而是一条能被现场操作和复现的业务闭环：

```text
多源数据接入
  → 清洗、质控、时空对齐
  → 遥感/藻类参数反演与校准
  → 机理模型 + 两种以上 AI 模型
  → 级联融合 / 残差融合
  → 多指标、多时间尺度预测
  → SHAP、敏感性与置信区间
  → 风险网格与 3D 时空推演
  → 自动预警、预案匹配、处置留痕
  → 模型评估与版本回滚
```

演示主线固定为：

1. 在 3D 驾驶舱看到当前太湖高风险区域和预警。
2. 点击贡湖湾站点进入站点研判，确认叶绿素 a、水温、总磷等异常。
3. 发起未来 7 天融合预测，观察任务进度和置信区间。
4. 打开解释页，说明高风险的主要正负驱动因素。
5. 在风险推演页播放水华扩张过程，并从高风险网格生成预警。
6. 在预警中心匹配预案、模拟推送、记录处置并关闭事件。
7. 在模型评估页展示融合模型相对单模型的真实指标变化；未达到 10% 时必须如实显示，不得伪造。

## 1. 设计原则与边界

### 1.1 必须坚持

- **契约冻结**：页面只依赖 OpenAPI/Pydantic 契约，不依赖模型内部实现。
- **占位不等于随机**：真实算法未接入前，使用同输入同输出的确定性占位器，并在 UI 标明 `placeholder`。
- **3D 是入口，2D 是证据**：3D 负责态势感知，2D 负责数据密度、可解释性和可核验性。
- **同一时刻一致性**：驾驶舱首屏使用一个快照接口，不允许 KPI、站点、热力和预警来自不同 `as_of`。
- **长任务异步化**：预测、反演、训练、数据接入返回 `202 Accepted`，通过 WebSocket 事件更新，断线后轮询兜底。
- **写操作可追溯**：预警处置、模型启用、数据发布均记录操作者、时间、前后状态、请求 ID。
- **断网可演示**：字体、纹理、地图简化边界、JS 依赖和示例数据全部本地化。
- **科学诚实**：模拟数据、反演数据、实测数据、插值数据必须带 `data_provenance`；任何指标不能伪造。

### 1.2 当前范围

- 空间对象：太湖 8 个示范站点和 11×19 风险网格；结构允许扩展到任意湖库。
- 预测对象：叶绿素 a、藻密度、蓝藻生物量、水华面积、风险概率、风险等级。
- 时间尺度：1—3 天短期、7—15 天中期、30—90 天长期。
- 终端：1920×1080 答辩大屏优先，兼容 1366×768；移动端只提供只读摘要，不实现完整 3D 操作。
- 首版不做真实短信/邮件发送，只做可审计的模拟推送；生产部署时再接第三方通道。

### 3.3 技术实现纠偏

- three.js 当前 WebGLRenderer 以 WebGL 2 为基础，启动时先探测能力；失败时进入 2D 降级模式。
- `OrbitControls` 开启阻尼或自动旋转时，每帧调用 `controls.update(delta)`。
- Vue 组件卸载时遍历释放 geometry、material、texture，停止 rAF、移除监听并调用 renderer/controls 的 `dispose()`。
- FastAPI 每个路由声明 Pydantic 输出模型，用于返回校验、OpenAPI 文档和字段过滤。
- SQLite 只作为单机演示库；启用 WAL、外键和 busy timeout，但不承担多节点任务队列。

### 4.1 视觉

- 背景：`#06111F`；一级面板：`rgba(9, 28, 48, .88)`；描边：`rgba(34, 211, 238, .22)`。

### 4.2 全局页面状态

| 状态 | 页面表现 | 用户动作 |
|---|---|---|
| 首次加载 | 骨架屏；3D 先显示水面骨架，再挂载数据对象 | 可离开页面 |

### 4.3 状态管理边界

- `appStore`：用户、权限、网络、WebSocket 状态。
- `contextStore`：`asOf`、`stationId`、`metricCode`、`forecastScale`，同步 URL query。
- `cockpitStore`：3D/2D、相机、自动旋转、时间轴播放；不存服务端事实数据。
- `jobStore`：异步任务状态；刷新页面后根据 `job_id` 恢复。
- 服务端数据由 Query 缓存管理，Pinia 不复制整份接口结果。

## 5. 统一 API 契约

### 5.1 基础约定

- Base URL：`/api/v1`
- Content-Type：`application/json; charset=utf-8`
- 时间：ISO 8601，统一 UTC 存储，响应带时区偏移，例如 `2026-08-09T14:30:00+08:00`。
- 数字：无数据用 `null`，禁止用 `-999`；比例统一 0—1，展示层转百分比。
- 枚举使用稳定英文 code，中文名使用独立字段。
- 每个响应均带 `request_id`；快照型响应带 `as_of` 和 `data_version`。
- 写接口头：`Idempotency-Key: <uuid>`；同键同请求返回首次结果。

成功响应：

```json
{
  "code": "OK",
  "message": "success",
  "data": {},
  "request_id": "req_01J5...",
  "server_time": "2026-08-09T14:30:00+08:00"
}
```

错误响应：

```json
{
  "code": "VALIDATION_ERROR",
  "message": "forecast_scale must be one of short, medium, long",
  "details": [{"field": "forecast_scale", "reason": "invalid_enum"}],
  "request_id": "req_01J5..."
}
```

分页响应的 `data` 固定为：

```json
{
  "items": [],
  "page": 1,
  "page_size": 20,
  "total": 0,
  "has_next": false
}
```

### 5.2 HTTP 状态码

| 状态 | 使用场景 |
|---|---|
| 200 | 查询、幂等更新成功 |
| 201 | 新建资源完成 |
| 202 | 异步任务已接受 |
| 204 | 无响应体删除/取消完成 |
| 400 | 业务参数无效 |
| 401/403 | 未登录/权限不足 |
| 404 | 资源不存在 |
| 409 | 状态冲突或幂等键冲突 |
| 422 | Schema 校验失败 |
| 429 | 频率限制 |
| 500 | 未处理异常；必须返回 request_id |
| 503 | 模型或数据依赖暂不可用 |

### 5.3 异步任务

提交响应统一为：

```json
{
  "code": "ACCEPTED",
  "message": "prediction queued",
  "data": {
    "job_id": "job_01J5...",
    "resource_id": "pred_01J5...",
    "status": "queued",
    "poll_url": "/api/v1/jobs/job_01J5..."
  },
  "request_id": "req_01J5...",
  "server_time": "2026-08-09T14:30:00+08:00"
}
```

状态枚举：`queued | running | succeeded | failed | cancelled`。WebSocket 事件：

```json
{
  "event": "job.progress",
  "event_id": "evt_01J5...",
  "data": {
    "job_id": "job_01J5...",
    "resource_id": "pred_01J5...",
    "status": "running",
    "progress": 65,
    "step": "fusion_prediction"
  }
}
```

前端 3 秒未收到事件时开始每 2 秒轮询；完成或失败后停止。浏览器刷新后从 URL/本地存储恢复未结束任务。

### 5.4 核心枚举

| 枚举 | 值 |

| `risk_level` | `none`, `low`, `medium`, `high`, `critical` |
| `data_provenance` | `observed`, `remote_sensed`, `interpolated`, `simulated`, `placeholder` |
| `warning_status` | `new`, `acknowledged`, `processing`, `resolved`, `closed` |

## 7. 算法接入协议

后端只调用固定协议：

```python
class PredictionEngine(Protocol):
    def predict(self, request: PredictionInput) -> PredictionOutput: ...
    def explain(self, request: ExplainInput) -> ExplainOutput: ...
    def metadata(self) -> ModelMetadata: ...
```

`PredictionInput` 至少包含：站点/区域、起报时间、时间尺度、指标列表、观测窗口、环境特征、模型集合、随机种子。`PredictionOutput` 必须包含：各模型逐时点结果、融合结果、区间、风险概率、风险等级、模型/数据版本和 provenance。

### 7.1 占位实现

- 使用固定参数和固定种子；同一数据版本 + 同一请求哈希必然同一结果。
- 温度、总磷、光照为正驱动；强降雨、流速为抑制驱动；站点有稳定偏置。
- 指标由种子数据真实计算，并在页面标注 `model_mode=placeholder`。
- 真实模型切换只改变依赖注入：`MODEL_MODE=real`，接口结构不变。

### 7.2 真实实现最低要求

- 至少一个可运行机理模型。
- 至少两种 AI 模型，时间顺序切分，防止未来信息泄漏。
- 至少级联与残差两种融合策略。
- 指标包含 R²、RMSE、MAE；风险分类可增加 AUC、F1、Brier score。
- 输出 SHAP 全局和局部解释、置信区间或风险概率。
- “提升 10%”使用预先冻结公式计算并显示实际值：例如 `improvement_rmse=(best_single_rmse-fusion_rmse)/best_single_rmse`。若为负数照实显示。

## 8. 3D 场景设计

### 8.1 场景层级

```text
Scene
├─ LakeSurface：64×64 水面顶点动画
├─ LakeBoundary：本地简化边界线
├─ RiskGrid：11×19 InstancedMesh/顶点色
├─ Stations：8 个浮标、标签、光柱
├─ BloomParticles：按风险帧重排的粒子
├─ WarningPulse：高风险脉冲环
└─ PickingLayer：扩大点击命中范围的透明代理对象
```

### 8.2 数据映射

- 经/纬度先归一化到湖区局部平面，坐标转换封装为纯函数并单测。
- 风险颜色只由 `risk_level` token 决定；高度由归一化 `risk_value` 决定。
- 档位切换使用 600—800ms 插值；收到新帧时保留旧帧到过渡结束。
- 站点点击使用 Raycaster，只检测 `PickingLayer`，避免对水面/粒子全量求交。
- 粒子数量按设备等级设置 1500/3000/5000；像素比上限 1.5。

### 8.3 性能目标

| 指标 | 目标 |
|---|---|
| 首屏可交互 | 本地环境 ≤ 3s |
| 3D 帧率 | 集显 1080p P95 ≥ 30fps |
| 档位过渡 | 主线程长任务 < 50ms |
| GPU 资源 | 连续进入/离开驾驶舱 20 次无持续增长 |
| 降级 | WebGL2 不可用时 2 秒内切换 2D |

## 9. 安全、权限与审计

- 演示版可使用本地固定账号，但权限守卫和后端角色校验都要存在，不能只在前端隐藏按钮。
- 上传文件限制扩展名、MIME、大小和路径；保存时使用服务端生成文件名，禁止路径穿越。
- 导出文件使用短期下载 token，不直接暴露磁盘路径。
- 预警关闭、模型启用/回滚、数据发布必须二次确认并写审计日志。
- 日志不得记录令牌、上传原始敏感内容或完整模型输入；以 request_id 串联。
- CORS 仅放行配置中的前端源；演示版也不使用 `*` 搭配凭据。

## 10. 测试与验收

### 10.1 测试分层

- 单元：风险分级、时间尺度、坐标映射、指标提升、状态机、幂等键。
- 后端集成：每个路由成功/错误/权限/空数据；数据库回滚；任务失败恢复。
- 契约：从 OpenAPI 生成 TS 类型；CI 检查破坏性变更。
- 前端组件：按钮禁用、加载、空态、错误态、确认弹窗。
- E2E：完整演示主线；WebSocket 断线切轮询；WebGL 降级。
- 性能：3D 帧率、接口 P95、数据库慢查询、资源释放。

### 10.2 全局 DoD

每个页面只有同时满足以下条件才算完成：

1. 正常、加载、空、错误、无权限五种状态均有实现。
2. 所有可点击元素在逐页指南中有唯一 UI ID 和明确后果。
3. 前端请求与 OpenAPI 返回类型一致，不使用 `any` 绕过。
4. 写操作有幂等、确认、成功反馈、错误反馈和审计。
5. Mock、占位、真实数据使用同一结构并明确 provenance。
6. 页面至少有一个自动化 E2E 场景。
7. 1366×768 不遮挡关键按钮，1920×1080 达到设计稿效果。

## 11. 开发计划与优先级

| Sprint | 前端 | 后端/算法 | 验收里程碑 |
|---|---|---|---|
| S0 契约 | 路由、tokens、状态组件、API 类型 | 工程、迁移、统一响应、种子数据、OpenAPI | 健康检查和 9 页面空壳 |
| S1 态势 | P01、P03、P07 的 2D/3D 基础 | 快照、站点、观测、风险帧 | 站点点击和时间轴联动 |
| S2 数据 | P02、P04 | 接入、质控、反演任务 | 上传→质控→发布一条链 |
| S3 模型 | P05、P06、P09 | 预测、解释、评估、占位算法 | 异步预测→解释→对比 |
| S4 闭环 | P08、全局 WebSocket | 预警状态机、预案、推送、审计 | 风险→预警→处置→关闭 |
| S5 真实算法 | UI 替换占位标识与报告 | 真实模型、真实指标、模型版本 | 模型可切换和可回滚 |
| S6 打磨 | 响应式、性能、离线、录屏 | 压测、备份、部署文档 | 断网完整演示 |

P0：P01、P03、P05、P06、P07、P08；P1：P02、P04、P09。若时间压缩，P1 页面仍保留可演示最小闭环，不删除赛题证据。

## 12. 借鉴与改造说明

- 借鉴同类智慧水利大屏的“中央地图 + 两侧态势面板”，但将装饰性大屏改成可点击、可回溯的业务入口。
- 借鉴 WQMFS 的太湖水质与多模型比较思路，但统一为多指标契约，不把页面写死为单一水质字段。
- 借鉴残差补偿 HybridModel 的结构思想，但指标、数据切分和实现必须由本项目独立实验产出。
- 借鉴 three.js 官方 OrbitControls、Raycaster 和资源释放模式，限制粒子、像素比和求交对象，保证答辩电脑可运行。
- 借鉴 SHAP 官方 beeswarm/waterfall 的信息层级，分别呈现全局与单样本解释，不用无意义的装饰图替代。
- 借鉴 FastAPI 的 response model、WebSocket 和后台任务能力，形成可校验契约与任务进度；计算密集模型在生产版应迁出 Web 进程。
