# 成员C机理-AI融合建模设计 V0.1

## 目标

建立成员C可交付的算法子系统骨架：机理模型、两种AI模型接口、两种融合策略、评估与解释模板、统一预测函数。当前真实训练数据尚未到位，因此本阶段只证明流程、接口和验收方式可运行，不声明真实预测精度。

## 边界

- 输入数据可先使用模拟样例或里程碑已有特征表。
- 不把模拟数据、单日标签或无时间交集数据描述为真实训练结果。
- 不提前承诺融合模型精度提升10%。
- 真实数据到位后，优先替换输入适配器，不重写算法接口。

## 架构

算法子系统分为六个模块：

1. `mechanism.py`：Logistic增长与Monod限制函数，输出机理风险指数。
2. `ai_models.py`：两种AI模型统一接口，当前使用可复现的轻量基线模型占位。
3. `fusion.py`：级联融合与残差融合。
4. `evaluation.py`：回归、分类和融合提升指标。
5. `explainability.py`：特征重要性、敏感性分析和不确定性区间模板。
6. `predictor.py`：统一预测函数，返回后端可调用的标准JSON。

## 数据流

标准样本表进入算法层后，先计算机理输出，再进入AI模型和融合策略。模型输出经过评估、解释和不确定性包装，最后由统一预测函数返回多指标、多时间尺度结果。

## 交付物

- 算法路线说明与任务计划。
- 可运行Python包 `blue_algae_m7`。
- 单元测试。
- 样例数据生成脚本。
- 统一预测JSON样例。
- 成员C README 和后续真实数据接入清单。

## 验收标准

- 机理模型可运行，并能响应温度、光照、营养盐变化。
- 两种AI模型接口可训练、可预测。
- 两种融合策略可输出结果。
- 评估模块能计算基础指标。
- 统一预测函数输出字段不写死为单一叶绿素指标。
- 测试通过，且文档明确当前结果不是正式模型精度。
