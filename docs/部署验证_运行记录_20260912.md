## 3. 一键启动（start-a23-dev.ps1）实测

### 3.1 原文件在 PowerShell 5.1 下解析失败（阻断）

```
PS D:\...\01_我们的开发> powershell -NoProfile -ExecutionPolicy Bypass -File start-a23-dev.ps1
所在位置 start-a23-dev.ps1:23 字符:19  表达式或语句中包含意外的标记"澶嶇敤宸茶繍琛岀殑"。
所在位置 start-a23-dev.ps1:38 字符:58  字符串缺少终止符: "。
ParserError ...  PS_EXIT=1
```

原因：文件为 UTF-8 **无 BOM**，Windows PowerShell 5.1 按 GBK 误读中文字符串导致引号失配、解析失败。看板第十节"ps1 必须 UTF-8 BOM"的教训在本机（且无 pwsh 7）被实证为**当前阻断项**。`scripts/check-a23-backend.ps1` 同样解析失败。

### 3.2 带 BOM 副本验证（证明只差一个 BOM）

方法：复制原文件内容到 `scripts/_tmp_start_verify.ps1` 并加 UTF-8 BOM（**原文件未动**，副本验证后已删除）。在 PS 5.1 下运行：

```
复用已运行的 A23 后端：http://127.0.0.1:8000/api/health
A23 前端已启动：http://127.0.0.1:5173     （5173 实际被占，vite 顺延端口）
PS_EXIT=0
```

- "复用已运行 A23 后端"分支正确触发：身份检查（/api/health → data.product_id）与幂等复用逻辑工作正常。
- 后端身份 / api_version=2.2.0 与当前代码一致；经 5174 端口 curl `/api/health` 亦返回 A23 身份（前端代理链路可用）。
- 注：5174 在验证前已有一个 05:41 启动的既有 vite 实例（PID 300，非本次拉起，未做改动）；本次验证拉起的临时 npm/vite 进程已全部结束并核实，5173/5174 原服务未受影响。

### 3.3 一致性核查结论（内容 vs 当前入口）

一致项：
1. 启动入口 `backend/.venv/Scripts/python.exe -m uvicorn backend.main:app` —— 与 backend/main.py 的 `app` 一致，venv 存在。
2. 身份检查 `/api/health` → `data.product_id == 'taihu-a23-algae-warning'` —— 与 main.py:246-258 一致。
3. `$env:BACKEND_ORIGIN` 传入后由 vite.config.js 读取做 /api、/rs 代理 —— 一致；换端口时代理自动跟随。
4. 前端 `npm.cmd run dev -- --port 5173` 与 package.json dev / vite.config.js server.port 一致。
5. 后端幂等与"非 A23 占用时拒绝启动、不杀用户进程"设计 —— 与红线一致，实测有效。

不一致/风险清单（建议小修，本 T6a 未改该文件）：
1. **【阻断】两个 ps1 均缺 UTF-8 BOM**，在系统默认 PS 5.1（本机无 pwsh）下无法解析。建议：给 `start-a23-dev.ps1`、`scripts/check-a23-backend.ps1` 补 BOM（1 字节、零语义变化）。
2. 【提示口径】前端启动无幂等/无健康验证：重复执行会叠加 vite（本机已发生），提示的 5173 可能非实际端口（顺延 5174+）。建议：启动前探测 5173，被占则提示复用或结束旧实例；或 vite 加 `--strictPort`。
3. 【默认参数】`-BackendPort` 默认 8000：端口占用是动态的（当日即 8000=A23、8001=他项目），默认值本身安全（有身份守卫），但建议在文档/脚本帮助中显式给出 `-BackendPort 8001` 的换端口示例。
4. 【文档差异】`A23_环境与部署说明_V1.0.docx` §5.1 声称"一键启动系统.bat / 一键停止系统.bat 可用"——**项目根不存在这两个 .bat**，且文档通篇未引用 start-a23-dev.ps1；文档"演示优先预览模式（4173，npm run preview）"与 ps1 只启动 dev（5173）不一致。三者的口径需在终审前统一（要么补 .bat、要么改文档指向 ps1）。
5. 【数据包联动】start-a23-dev.ps1 不设置 `TAIHU_REALTIME_CATALOG_DIR`，即一键启动不自动挂小型数据包实时目录（用 data-cleaning 下的运行时目录）。若评审按"数据包 README"操作需手动设 env，两套入口的差异应写入部署说明。
