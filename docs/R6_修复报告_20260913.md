## 2. R5-03（高）：校准合同补单类别否决

**修复内容**：`_build_uncertainty`（predict_suite 与批量共用）此前调用 `_calibration_verdict` 未传 `class_support`——合同里 2026-09-12 已写好的单类别判定（`CALIBRATION_SINGLE_CLASS_TEST`）在模型路径上形同虚设。现按 bundle 的 `problem_type ∈ {binary, probability}` 从 `runs/<run>/test_predictions.csv` 统计留出测试段 actual 分布（同 `_row_level_degeneracy` 的 run 名构建口径，带缓存），任一侧为 0 即 `class_support_sufficient=false` → 判 `single_class_test`、`decision_usable=false`，理由带正/负例计数。CSV 不可得返回 None（不猜测，维持既有判定）；回归/ordinal 任务不适用。快照 `CACHE_SCHEMA_VERSION` 递增至 v12，旧快照不再以旧语义服务。

**自证（改前/改后探针，同代码同输入对照）**：

| 对象 | 改前 | 改后 |
| --- | --- | --- |
| T+90 probability（T6-probability-90d-3m-cv，test_n=28 全负例，coverage=1.0） | `validated` / `decision_usable=True` | **`single_class_test` / `decision_usable=False`**，理由="独立测试段只含单一类别样本，覆盖率不构成判别力证据，仅反映该类覆盖（正例 0、负例 28，n=28）" |
| T+1/T+15 bloom & probability（pos=2/neg=38 双类别） | `validated` | `validated`（无误伤，class_support_sufficient=true） |
| T+30/T+60 bloom & probability（n=5 全负例） | `insufficient_test_evidence` | `insufficient_test_evidence`（样本量判定先于单类别，顺序正确） |

**服务行为后果（重启后端探针，快照 v12 = `PRED_..._384085ccddc1`）**：T+90 probability 行（全湖与站点 mee-0145cdb7 双口径）`value_origin=v0_3_real_bundle`、`calibration_status=single_class_test`、`decision_usable=false`——R5 §4.3 所述"平凡 100% 覆盖驱动 T+90 概率层服务行为"已被单类别否决阻断。T+90 `risk_level` 仍由 chla 源（88.89%，回归任务不受单类别否决）派生，与 acceptance_e2e 的 K3 兼容断言一致（该项 PASS）。

## 5. F-1（中）：apply_action 落盘原子性 + O-1 请求级日志

**修复内容**（`backend/app/alert_center.py`）：顺序由"先 `_audit` 后 `save_events`"调换为**先 `save_events` 成功再写 audit**；save 失败→不写成功审计、`logger.exception` 记请求级堆栈（event/action/actor）后原样上抛（API 500）；audit 失败→`logger.exception` 记日志但**不让请求 500**（业务事实已发生，报错会诱发重复操作，审计缺口交日志告警复核）。新增模块级 `logger = logging.getLogger(__name__)`（修 O-1：此前 500 无堆栈可查）。

**自证（行为级，注入临时目录假 store/engine，不触实库）**：

| 场景 | 结果 |
| --- | --- |
| A：save_events 抛 OSError（模拟 Windows temp.replace 瞬态失败） | 异常上抛=True；audit 中 submit_review 成功记录数=**0**（修复前会残留"成功"审计——即 R4 实测的不一致窗口） |
| B：_audit 抛 OSError | 返回事件 status=review、records=1（业务生效、未 500），异常入日志 |

瞬态文件占用无法在真实负载下稳定复现（R4 的 500 三分钟自愈即此性质），故以注入式行为验证 + 代码审查（两个文件无事务，顺序决定一致性方向：现在不一致只可能剩"业务生效、审计缺失"且有日志可查）作为验证方式。
