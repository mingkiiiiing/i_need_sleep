# 多源数据样本集说明 V0.1

## 1. 数据用途与版本

本说明覆盖当前建模链路使用的样本数据：

```text
数据名称：TAIHU_GRID_SYNTHETIC_AUGMENTATION_V0.4
粒度：grid_id + date
声明：synthetic_development_only
```

该数据用于验证：

- 数据接入、清洗和时空对齐；
- 机理过程与 AI 算法；
- 多时间尺度预测；
- 模型选择与测试隔离；
- 解释性和不确定性流程。

该数据不用于声明真实太湖预测精度。

## 2. 数据来源类型

数据按来源分为：

| 类型 | 示例 |
|---|---|
| 气象 | 气温、降水、风速风向、辐射 |
| 水质 | 水温、TN、TP、DO、pH |
| 水文/水动力 | 水位、流速、混合指数 |
| 遥感 | 叶绿素、藻蓝蛋白、密度代理、FAI、NDCI |
| 空间 | 网格、湖区、面积、坐标 |
| 生态目标 | 蓝藻密度、生物量、叶绿素 a |
| 标签 | 水华发生、面积、覆盖率、风险等级 |

## 3. 时间与空间

### 3.1 时间

- 日粒度；
- 覆盖年份：2005-2025；
- 预测起点日期与目标日期分离；
- 目标日期 `date + h`。

### 3.2 时效

```text
T+1、T+3、T+7、T+15、T+30、T+60、T+90
```

### 3.3 空间

- 固定网格；
- 每湖区分区存储；
- 带 `water_area_m2`；
- 带网格中心坐标。

## 4. 字段字典

### 4.1 标识

| 字段 | 含义 |
|---|---|
| `grid_id` | 网格标识 |
| `date` | 自然日 |
| `dataset_split` | train/validation/test |
| `data_version` | V0.4 |
| `claim_boundary` | synthetic_development_only |

### 4.2 气象字段

| 字段 | 单位 |
|---|---|
| `air_temperature_C` | °C |
| `precipitation_mm_day` | mm/day |
| `wind_speed_m_s` | m/s |
| `wind_direction_deg` | deg |
| `solar_radiation_MJ_m2_day` | MJ/m²/day |
| `relative_humidity_pct` | % |
| `surface_pressure_kPa` | kPa |

### 4.3 水质字段

| 字段 | 单位 |
|---|---|
| `water_temperature_C` | °C |
| `total_nitrogen_mg_L` | mg/L |
| `total_phosphorus_mg_L` | mg/L |
| `dissolved_oxygen_mg_L` | mg/L |
| `ph` | 无量纲 |
| `phytoplankton_biomass_mg_L` | mg/L |

### 4.4 遥感字段

| 字段 | 含义 |
|---|---|
| `remote_chlorophyll_a_ug_L` | 遥感叶绿素 |
| `remote_phycocyanin_ug_L` | 藻蓝蛋白 |
| `remote_cyanobacteria_density_cells_L` | 蓝藻密度代理 |
| `remote_fai_proxy` | FAI |
| `remote_ndci_proxy` | NDCI |
| `valid_pixel_ratio` | 有效像元比例 |

### 4.5 机理字段

机理生成字段包括：

- `temperature_factor`
- `nitrogen_factor`
- `phosphorus_factor`
- `nutrient_factor`
- `light_factor`
- `capacity_factor`
- `gross_growth_rate_d`
- `respiration_rate_d`
- `mortality_rate_d`
- `mixing_loss_rate_d`
- `net_growth_rate_d`

单位：

- 因子：无量纲；
- 速率：`day^-1`。

## 5. 标签定义

### 5.1 T1 水华发生

`bloom_label = 1/0`，仅在有效观测和完整覆盖下确定。

### 5.2 面积与覆盖率

- `bloom_area_km2`
- `bloom_coverage_ratio`

### 5.3 连续目标

- `cyanobacteria_density_cells_L`
- `blue_algae_biomass_mg_L`
- `chlorophyll_a_ug_L`

### 5.4 风险

- `bloom_risk_level`：none/low/medium/high/severe
- `bloom_probability`

## 6. 缺失与质控

### 6.1 标签缺失

- 无覆盖、无观测、质量不合格不写成负样本；
- `unknown` 不进入监督损失。

### 6.2 特征缺失

- 只使用训练数据拟合中位数插补器；
- 增加显式缺失指示；
- 不跨切分使用未来数据插补。

### 6.3 质控

- 检查主键唯一；
- 检查时间连续；
- 检查跨切分泄漏；
- 检查目标日期是否等于 `date + h`；
- 检查测试集是否冻结。

## 7. 派生特征

### 7.1 机制特征

由基础字段实时计算，不存储隐藏真值。

### 7.2 日历特征

```text
calendar_day_of_year_sin
calendar_day_of_year_cos
calendar_day_of_week_sin
calendar_day_of_week_cos
```

### 7.3 历史特征（可选）

```text
lag 1/3/7/14/30 日
rolling7 mean
rolling7 std
change_1d
change_7d
```

## 8. 最终模型输入契约

完整模型包 `算法模型交付包_完整版_V0.2/models/` 中每个模型要求输入：

- 模型原始特征字段；
- `features` 为与字段名一致的 JSON 对象；
- 请求包含 `task_id`、`variant`、`horizon_days`；
- 样例见 `sample_inputs/*.json`。

特征单位必须与 V0.4 字段字典一致。模型内部完成中位数插补和缺失指示，前端无需自行实现。

## 10. 可追溯性

- 数据包只读；
- Manifest 和 QA 报告带版本；
- 代码运行记录保存数据摘要；
- 输出 run 记录 `data_version`；
- 派生特征不写回原包。

## 11. 已知限制

1. 当前是合成数据；
2. 没有真实天气预报字段；
3. 缺失处理不能替代真实业务数据接入；
4. 不能把 V0.4 模拟结果用于真实太湖精度声明。
