# 太湖蓝藻完整数据生成、处理与训练系统设计 V1.0

生成日期：2026-09-04  
适用工程：`项目完整汇总_2026-08-31/01_我们的开发`  
文档性质：系统总体设计、数据生成规范、工程实施方案、训练数据契约与验收依据

## 1. 结论先行

可以采用“第三方项目的数据生成思想 + 我方真实数据约束 + 我方清洗处理链 + 我方算法”的路线，但不能直接把第三方项目生成的数据当成真实观测，也不能用月度或年度数据插值制造逐日真实标签。

本项目应在现有统一工程内新增一个 **Data Factory（数据工厂）**，只吸收第三方项目“生成数据”的方法论，不采用其前端、后端和算法。数据工厂负责：

1. 接入并冻结真实历史数据和实时接口快照；
2. 统一站点、湖区、1 km 网格、时间、单位和质量标记；
3. 使用训练期真实数据估计季节规律、变量关系、空间相关性和观测误差；
4. 通过机理约束的随机过程生成连续逐日、逐网格的潜在生态状态；
5. 再通过“观测模拟器”产生遥感云遮、站点缺测、测量误差和发布时间；
6. 生成七类任务、五个预测时效所需标签与特征；
7. 经过现有清洗、对齐、特征、切分、门禁和血缘流水线；
8. 输出可以直接被成员 C 算法读取的标准训练样本。

系统必须并行发布三条轨道：

| 发布轨道 | 数据内容 | 可以用于 | 不可以宣称 |
|---|---|---|---|
| SIM-V1 | 全量机理约束仿真，标签为 `simulation_truth` | 算法开发、接口联调、消融、压力测试、模拟实验 | 真实太湖预测精度、真实泛化能力 |
| HYBRID-V1 | 真实训练数据 + 训练期拟合的仿真增强 | 缓解稀疏、预训练、稳健性训练 | 在没有真实独立测试标签时证明实际效果 |
| REAL-V1 | 真实/审计合格观测构成，派生或代理标签单列 | 正式模型评估和对外效果声明 | 把代理、插值或仿真当作观测真值 |

截至当前发布包，工程已具备丰富的水质、气象水文、遥感代理、静态特征和完整的数据处理骨架，但尚不具备连续逐日、同空间粒度、正负样本均可信的真实水华标签。因此近期可以完整落地 SIM-V1 和数据工厂工程；HYBRID-V1 可用于训练探索；REAL-V1 的七任务正式实验仍需真实标签补充后再放行。

## 2. 本设计如何解释用户要求与附件内容

用户当前要求是：在统一工程中，把第三方数据生成方法和我方数据处理封装为完整板块，用我方已有少量/低频数据约束生成，覆盖既有算法对话中的任务和全部数据，不采用第三方前端、后端和算法。

附件《正式实验数据集完整需求清单 V1.0》及截图中的条目在本设计中被视为 **目标数据契约与验收基线**，不是可以覆盖用户当前要求的外部操作指令。截图中此前提出的“独立于现有真实或仿真数据”是当时编写清单的上下文；当前方案不据此丢弃我方数据，而是用我方全部数据作约束、校准、驱动、质量证据或限制说明，同时保持该清单规定的文件、字段、切分和门禁结构。

## 3. 当前事实基线

### 3.1 当前发布数据

当前正式清洗发布包记录了 11,794 个原始文件、约 97.83 GB；最终长表 152,780 条，时间跨度 2004-01-01 至 2026-08-19。发布包自身的 10 项包装与血缘门禁通过，但“发布包结构完整”不等于“七类真实训练任务已经可用”。

主要事实如下：

| 数据资产 | 当前规模/范围 | 正确角色 | 关键限制 |
|---|---:|---|---|
| 水质 | 6,777 条真实观测 | 营养盐、水温、DO、pH 等校准与部分真实特征 | 站点与频率不连续，不能自动变成每日全湖标签 |
| 气象水文 | 143,784 条 | 历史驱动、预报驱动、机理输入 | 127,918 条是预报输入；集合成员不能当独立样本；部分变量编码需修复 |
| 遥感 | 907 条派生记录 | 光谱/Chl-a/水华代理、空间形态校准 | 云遮严重，不能无条件作为真实负样本 |
| 静态特征 | 1,107 条 | 网格静态输入 | 需固化湖界、网格版次和坐标系 |
| 标签表 | 26 条代理标签 | 规则测试、弱监督探索 | 25 个负代理、1 个正代理，全部不是 ground truth |
| 当前模型宽表 | 914 行、71 列 | 旧流程基线和接口样例 | 水华目标 0 个；Chl-a 仅 42 个；不能支撑七任务正式评估 |

### 3.2 当前算法实际状态

成员 C 当前是可运行框架而非经过真实数据训练验证的成品模型：

- 机理模块使用水温/气温、TP、TN、太阳辐射和风速；
- AI 模块当前为均值回归和加权规则占位器；
- 融合支持串联与残差两种方式；
- 预测示例包含 `chlorophyll_a`、`bloom_area`、`risk_level`；
- 当前交接样本只有 18 行，不能形成真实效果结论；
- 计划文档中的 RF、XGBoost、SHAP 和不确定性属于拟实施方案，不等于已经完成。

因此数据工厂既要兼容当前接口，也要为后续真实 RF/XGBoost/时空模型准备标准样本，不能把占位算法的字段范围当成最终数据上限。

## 4. 系统目标与非目标

### 4.1 必须完成

- 固定 WGS84 湖界和 1 km × 1 km 水域网格，提供网格版本和映射表；
- 至少生成连续五年逐日数据，含闰日，支持更长历史情景；
- 粒度为“一个空间单元在一个北京时间自然日一行”；
- 同时覆盖站点、网格、湖区三种空间层级；
- 覆盖 T1–T7 七项任务和 T+1/T+3/T+7/T+15/T+30 五个时效；
- 覆盖水质、气象、水文、遥感、静态、机理、质量、血缘、标签和切分字段；
- 支持历史批量数据、实时接口和离线回放；
- 同一套输出可直接供现有算法适配器和后续正式模型使用；
- 固定随机种子、配置、代码版本、输入哈希，可完全复现；
- 对真实、派生、代理、仿真和未知状态作机器可读区分。

### 4.2 明确不做

- 不复制第三方前端、后端、账户系统或算法；
- 不把生态环境部实时接口当作历史训练标签的唯一来源；
- 不用月度/季度/年度值线性插值后标记为逐日观测；
- 不从未来日期构造当前特征；
- 不让验证集和测试集参与生成器参数拟合；
- 不用合成样本扩增验证集或测试集；
- 不把云遮、无文件、未覆盖、接口异常写成无水华；
- 不把仿真精度包装成真实水华预警精度。

```text
历史真实文件 ─┐
实时官方接口 ─┼─> 原始不可变区 -> 标准化/QC -> 时空主数据 -> 时间切分冻结
第三方公开数据 ┘                                         │
                                                         ├─> 真实数据特征/标签链 -> REAL-V1
                                                         │
                                                         └─> 仅用训练期拟合校准器
                                                                      │
气象历史/预报/情景 -> 外源驱动 -> 机理随机模拟 -> 潜在生态真值 -> 观测模拟器
                                                │              │
                                                │              ├─> SIM-V1
                                                │              └─> 与真实训练样本合并 -> HYBRID-V1
                                                │
                                                └─> 七任务标签与多时效样本

三条轨道 -> 现有清洗/对齐/特征/标签/门禁/血缘 -> 成员 C 算法适配器 -> 训练/验证/测试
```

新增能力作为 `data-cleaning/data_factory` 子模块进入统一工程；现有 `data-cleaning/pipeline` 继续负责清洗、重采样、对齐、特征、覆盖、标签、切分和发布，不另建割裂工程。

## 6. 所有数据的生成逻辑

### 6.1 两层世界：潜在真值与可见观测

生成过程必须分成两层：

1. **潜在生态真值层**：描述每个网格每天真实存在的水温、营养盐、蓝藻、叶绿素、水华覆盖和风险；这是仿真世界内部的真值。
2. **观测层**：模拟站点采样、卫星过境、云遮、检测限、仪器误差、缺测、延迟和接口中断；算法实际只能看到这一层。

如果直接把生成值全部当作可见特征，模型会获得现实中不存在的完美观测；如果先制造缺测再生成真值，又无法区分“没有水华”和“没有观测”。因此顺序必须是：先生成潜在真值，再生成观测和可用性。

### 6.2 固定空间骨架

- 使用审计通过的正式太湖边界；
- 在等面积或米制投影中建立 1 km 网格，再存储 WGS84 几何；
- 仅保留与水面相交的网格，记录 `water_fraction`、交叠面积和有效面积；
- 为每个网格生成稳定 `grid_id`，并冻结 `grid_version`；
- 建立站点到网格、湖区到网格、入湖河道到邻近网格的版本化映射；
- 面积计算使用投影几何，不使用 JPG 像素面积或经纬度平面面积。

### 6.3 静态状态

每个网格的静态向量包括：经纬度、有效水面积、湖区、岸线距离、平均/最小/最大水深、底高程、坡度、入湖口距离、土地利用比例、植被覆盖、历史营养负荷分区、遥感可观测性和站点覆盖等级。

真实静态数据存在时直接使用；缺失项采用有证据的空间插值或分区先验，并写为 `derived`，不能写为观测。静态字段随 `grid_version` 冻结。

### 6.4 外源气象驱动

优先级为：真实历史气象/再分析 > 正式预报归档 > 训练期拟合的气象情景生成器。

气象情景生成不能只是“正弦曲线 + 白噪声”。每个变量按以下结构产生：

`X(g,t) = 季节项(doy) + 年际项(year) + 天气过程项(t) + 空间场项(g,t) + 极端事件项 + 残差`

- 季节项由训练期逐日气候态和平滑周期函数估计；
- 天气过程项采用保持连续性的 AR/VAR 或分块自举；
- 降雨用发生过程 + 强度分布的两阶段模型；
- 温度、湿度、辐射、风和降雨的相关性用联合残差/协方差或 copula 保留；
- 空间场采用相关随机场，不能让相邻网格完全独立；
- 极端热浪、静风、暴雨和台风扰动单独建情景；
- C3S 集合成员作为同一次预报的不确定性成员，不能拆成独立真实日样本。

### 6.5 水温生成

水温由气温、前一日水温、太阳辐射、风速、水深和季节热惯性共同决定：

`Tw(t) = Tw(t-1) + k1*(Ta-Tw) + k2*Radiation - k3*WindMixing - k4*DepthEffect + ε`

系数按湖区/月份分层校准，并设物理范围、日变化率和冻结/高温限制。ERA5 湖温只作为派生约束；实测水温用于误差校准和真实评估。

### 6.6 水文与水量平衡

每日水位/水深/流量根据：前一日水位、入湖流量、出湖流量、降雨、蒸发和风生增减水生成。无完整流量数据时，先用训练期水位/流量季节分布拟合受约束状态空间模型；模拟结果标记为 `simulated`。

必须保证：水深非负、变化率合理、强降雨后流量响应有时滞、入湖口邻域响应更强、同一天全湖水位不出现无物理依据的剧烈跳变。

### 6.7 营养盐与溶解氧

TP、TN、NH4-N 等由外源负荷、内部释放、藻类吸收、沉降/再悬浮、稀释和衰减组成：

`N(t+1)=N(t)+Load_N+Release_N-Uptake_N-Settling_N-Outflow_N+εN`

`P(t+1)=P(t)+Load_P+Release_P-Uptake_P-Settling_P-Outflow_P+εP`

DO 由水温饱和值、光合作用、呼吸耗氧、风浪复氧和有机质分解决定。pH、浊度、透明度与藻量、悬浮物和风浪相关生成。

参数采用分层估计：全湖先验 + 湖区偏差 + 季节偏差；稀疏站点向全湖先验收缩，避免用少量数据拟合出极端关系。

### 6.8 蓝藻生物量和密度

蓝藻潜在生物量采用带环境限制的增长—损失方程：

`B(t+1)=B(t)+[μmax*fT(Tw)*fN(N)*fP(P)*fI(Rad)-Resp-Mort-Grazing]*B*(1-B/K)+Transport+εB`

其中：

- `fT` 为适温范围响应；
- `fN=N/(KN+N)`、`fP=P/(KP+P)` 为 Monod 限制；
- `fI` 描述光照限制和过强光抑制；
- 风速控制垂直混合和表层聚集；
- 携带量 K 随湖区、水深和营养状态变化；
- 损失项包含呼吸、死亡、摄食和冲刷。

蓝藻密度、蓝藻生物量、叶绿素 a 不能互相简单复制。三者由潜在群落状态通过训练期校准的条件分布联系，并加入生理状态和测量误差：

- `density = B / cell_mass * composition_factor`
- `chl_a = B * pigment_ratio(T, light, nutrient) + non_cyano_chl + error`
- 月度蓝藻生物量和年度/低频蓝藻密度只约束季节尺度分布，不被插值成逐日观测。

### 6.9 空间迁移与聚集

网格之间建立邻接图，每日执行受风向、风速、流场、水深和岸线约束的平流—扩散：

`B_g(t+1) += Σ_h A(h,g,t)*B_h - Σ_h A(g,h,t)*B_g + D*L(B)`

低风、适温、高营养时增加表层聚集概率；岸线、湾区和下风向网格可形成空间簇。所有随机扰动使用具有空间相关长度和时间持续性的随机场，不能逐格独立撒噪声。

### 6.10 水华发生、覆盖和面积

水华潜在覆盖率不是直接随机生成，而是由表层蓝藻浓度、低风聚集、水温、光照和持续时间共同决定：

`bloom_fraction = sigmoid(a0+a1*surface_B+a2*calm+a3*Tw+a4*persistence+a5*shore_effect+ε)`

网格水华面积：`bloom_area_m2 = effective_water_area_m2 * bloom_fraction`。湖区/全湖面积为同日网格面积求和；几何范围由连续正网格或覆盖分数等值面生成，并提供 CRS、覆盖状态和源数据哈希。

### 6.11 遥感观测模拟

从潜在 Chl-a、蓝藻、浊度、CDOM 和水面状态生成可见光/近红外反射率，再计算 FAI、NDCI、MCI 等指数。随后叠加：

- 卫星过境日和传感器空间分辨率；
- 云、薄云、太阳耀斑、邻近效应和无效像元；
- 波段噪声、产品反演偏差和检测限；
- 有效覆盖率和质量位。

云遮或没有过境时 `label_status=unknown`，绝不自动写成负样本。真实 Sentinel-2、MODIS、CLMS 可校准覆盖率、指数分布和误差，但继续保留 `derived/proxy` 身份。

### 6.12 站点观测模拟

根据真实站点采样频率、工作日效应、季节性加密、仪器停机和检测限，从所在网格潜在状态抽样，产生：

- `observed_time`：采样/观测时间；
- `available_time`：该值可被系统使用的时间；
- `issue_time`：预测起报时间；
- 测量值、检测限、误差、质量标记和缺失原因。

接口中断只产生 `missing_reason=api_unavailable` 或过期缓存标记，不允许用模拟值悄悄替代观测值。

### 6.13 七类任务标签

| 任务 | 标签 | 生成/观测逻辑 |
|---|---|---|
| T1 | 水华发生 | 由同日有效覆盖与阈值形成；真实轨道须有观测证据，仿真轨道为 simulation_truth |
| T2 | 水华面积/覆盖率 | 等面积网格面积求和；必须带 CRS、覆盖率、几何与方法版本 |
| T3 | 蓝藻密度 | 实测优先；仿真由生物量与细胞质量关系生成，不拿年度值冒充逐日值 |
| T4 | 蓝藻生物量 | 实测优先；仿真由增长—损失—输运模型生成 |
| T5 | 叶绿素 a | 实测/审计合格反演分列；仿真保留非蓝藻叶绿素与误差 |
| T6 | 风险等级/概率 | 依据冻结的阈值 YAML 和目标变量计算，不作为上游输入泄漏给模型 |
| T7 | 空间范围 | 正网格集合、几何、多边形交叠面积和网格级标签 |

每项标签同时保存 `label_value`、`label_status`、`label_source_type`、`label_quality`、`is_ground_truth`、`is_synthetic`、`method_version` 和证据链接。

三态规则固定为：`observed_positive`、`observed_negative`、`unknown`。仿真发布可另有 `simulation_positive/simulation_negative`，但不能改写为 observed。

### 6.14 多时效样本

对每个起报日 T 生成 T+1/T+3/T+7/T+15/T+30 标签。特征只允许使用 `available_time <= issue_time` 的值。生成字段包括：

- 原始当日特征；
- 1/3/7/14/30 日滞后；
- 3/7/14/30 日滚动均值、标准差、最小、最大、有效计数；
- 1/7 日变化；
- 年内日、月份、季节；
- 机理模块中间因子、机理预测和不确定性；
- 未来气象预报只能使用起报时已经发布的预报版本。

标签连接键为 `spatial_id + issue_date + target_date + target_metric + horizon_days`，而不是只用月份或最近邻日期。

| 现有数据类别 | 进入数据工厂的角色 | 是否能做真实标签 | 处理原则 |
|---|---|---:|---|
| C3S 季节预报 | 外源预报情景与集合不确定性 | 否 | 按起报批次/成员保留，不将成员当独立真值 |
| ERA5 湖温 | 水温派生约束和缺口辅助 | 否 | 与实测分列，记录再分析来源 |
| 太湖水质/生物 | 营养盐、水温、Chl-a、生物量校准和部分观测 | 条件允许 | 保留站点、采样日期、单位和质量证据 |
| 水文 | 水位、流量、降雨响应驱动 | 否 | 先修复乱码变量码，统一单位 |
| 静态特征 | 网格固定属性 | 否 | 随网格版本冻结 |
| Sentinel-2 月产品 | 光谱/空间形态/覆盖校准 | 仅派生/代理 | 不能把月产品插成每日真值 |
| MODIS Aqua Chl-a | 遥感观测和误差/云率校准 | 仅派生/代理 | 仅有效像元；云日 unknown；截断文件拒绝 |
| 现场样本 | 真实观测与反演校准 | 条件允许 | 建立站点/时间/实验方法证据 |
| NOAA GFS | 短期预报驱动样例 | 否 | 按 issue_time 使用，不倒灌未来发布值 |
| CLMS 10 日产品 | 遥感辅助特征 | 仅派生/代理 | 保留原时间粒度和不确定性 |
| CLMS Chl-a 资产 | Chl-a 派生特征 | 仅派生/代理 | 不等价于蓝藻密度/水华面积 |
| 旧中间文件元数据 | 血缘与历史追踪 | 否 | 不从元数据推造观测值 |
| 旧未分类元数据 | 待分类证据 | 否 | 无法验证前保持 metadata_only |
| 公开门户元数据 | 来源登记与后续获取索引 | 否 | 不把链接存在当作数据可用 |
| MODIS L2 | 原始遥感候选 | 条件允许派生 | 做完整性、范围、像元和覆盖检查 |
| Sentinel-3 OLCI | 未来遥感候选 | 当前否 | 鉴权未完成保持 blocked_auth |
| 水华档案元数据 | 事件索引 | 条件允许 | 取得原始证据后才可制作事件标签 |
| THQBCA 档案元数据 | 数据来源索引 | 条件允许 | 取得可读记录后再决定用途 |
| MEE 月报/PDF 元数据 | 月度背景和来源登记 | 否 | 扫描 PDF 无可靠数值时不得 OCR 猜测 |

另外，错误 MODIS LST 瓦片不进入太湖建模；必须先确认正确覆盖瓦片。所有 19 类数据即使不能形成数值，也应进入 `source_registry`，其终态为 cleaned、derived、metadata_only、rejected、blocked_auth、duplicate 或 quarantined，不能在清单里消失。

## 8. 实时接口设计

生态环境部国家地表水水质自动监测系统接口在本系统中是 **实时/准实时水质观测来源之一**，不是训练数据生成器，也不是唯一历史数据来源。它可能提供断面或自动站的发布时间、指标值和状态，具体字段、授权、频率和使用条款必须按实际接口核实。

接入链：

1. 调度器按接口允许频率请求；
2. 原始响应原封不动写入 `raw_snapshot`，记录请求时间、HTTP 状态、响应哈希、接口版本；
3. 解析到规范字段并保存原字段；
4. 执行单位、范围、跳变、重复、时钟和站点身份检查；
5. 映射到正式站点和 1 km 网格；
6. 写入增量 Bronze/Silver/Gold 分层；
7. 预测时只读取在 `issue_time` 前已发布的值；
8. 接口失败时重试并标记，不以模拟数替代；允许显示最后有效值，但必须带 `is_stale=true` 和数据龄期。

历史回填使用官方归档、既有真实文件、再分析和经过许可的公开数据；实时接口只负责其实际覆盖时段。所有凭据保存在工程外的环境配置中，不进入发布包。

## 9. 数据契约与血缘

### 9.1 核心主键

- 网格日：`grid_id + date + dataset_version`
- 站点观测：`station_id + observed_time + metric + source_record_id`
- 训练样本：`sample_id = hash(spatial_id, issue_time, target_date, task_id, horizon, dataset_version)`
- 几何：`geometry_id + grid_version + valid_from + valid_to`

### 9.2 强制字段组

| 字段组 | 主要字段 |
|---|---|
| 标识 | sample_id、spatial_id、spatial_type、grid_id、station_id、region_id |
| 时间 | observed_time、available_time、issue_time、target_date、horizon_days、timezone |
| 质量 | quality_flag、coverage_ratio、missing_reason、detection_limit、qc_rule_version |
| 来源 | source_id、source_file_id、source_hash、source_type、source_record_id |
| 身份 | value_type、is_ground_truth、is_synthetic、label_status、label_source_type |
| 生成 | scenario_id、random_seed、generator_version、parameter_set_id、parent_record_ids |
| 空间 | crs、grid_version、geometry_id、effective_water_area_m2 |
| 版本 | schema_version、dataset_version、code_commit、config_hash、created_at |

`value_type` 枚举：`observed`、`derived`、`proxy`、`forecast_input`、`simulated`、`metadata_only`。空值用 null，不使用 -999 或 0 代替。

### 9.3 成员 C 适配器

新增 `member_c_adapter` 将标准训练样本转换为现有接口字段：

`date, sample_id, spatial_id, spatial_type, target_metric, target_value, target_unit, label_status, source_type, quality_flag`

并附加水温/气温、TP、TN、NH4-N、DO、pH、辐射、风、降雨、湿度、水位、流量、Chl-a、水华面积、蓝藻生物量、FAI/NDCI 及机理中间量。适配器只做字段映射和单位转换，不改变标签身份。

## 10. 防泄漏与数据切分

严格流程是 **先按真实自然时间切分，再拟合生成器**：

1. 同一天所有网格进入同一 split；
2. 按自然时间前 70%/中 15%/后 15% 切分；
3. train/validation 和 validation/test 之间各留至少 30 天隔离窗；
4. 任何标准化器、插补器、阈值校准器、遥感反演、分布拟合、生成器参数只用训练期；
5. 仿真增强只进入训练集；
6. 验证集与测试集保持真实、冻结、不重采样；
7. 测试集哈希写入 manifest，防止调参时悄然更换；
8. 每个特征验证 `available_time <= issue_time`；
9. 未来天气特征必须引用相应起报版本，不能使用事后再分析冒充当时预报；
10. 风险阈值和目标派生值不可反向作为同一任务输入。

若 SIM-V1 用于独立算法比较，应另外冻结未参与校准的情景种子、参数区间和极端事件作为 simulation test；其结论仍只适用于仿真世界。

## 11. 质量门禁与一票否决

三个发布轨道分别运行门禁，不能用 SIM-V1 的通过结果替代 REAL-V1。

### 11.1 必过检查

- 文件可读、Schema、主键唯一和全日期连续；
- 时间、时区、issue/available/target 关系正确；
- 单位、范围、坐标、湖界、网格版本合法；
- 站点—网格—湖区映射完整；
- 正/负/unknown 证据和覆盖率正确；
- 七任务、五时效样本均有明确统计；
- 每个 split 标签数量、正负平衡和特征完整度报告；
- 未来泄漏、日期交叉、实体交叉和派生目标回流审计；
- 真实/代理/仿真身份不可逆地保留；
- 生成配置、参数、随机种子、代码版本、哈希和血缘可复跑；
- 分布、相关性、季节性、极值、空间聚集和守恒/范围约束检查；
- 输出 21 项验收表和 12 项一票否决表。

### 11.2 一票否决

出现以下任一情况不得进入对应正式实验：

1. 用月度/年度插值冒充逐日真实标签；
2. 水华面积来自无地理参考图片或无法审计的人工估算；
3. 无文件、未覆盖、云遮或缺测被写成负样本；
4. 蓝藻生物量被直接当作浮游植物生物量而未说明；
5. 训练/验证/测试随机混排或日期交叉；
6. 使用未来实况、未来标签或事后信息构造特征；
7. 测试集被过采样、欠采样或用于调参；
8. 补出来的目标被当成真实观测；
9. 缺少空间 ID、正式边界、单位、质量和来源血缘；
10. 仿真数据被标成真实观测；
11. 数据无法复跑、核验、版本冻结或哈希不一致；
12. 任一核心任务在任一 split 没有足够有效标签。

附件建议的数量门槛继续执行：每个 split 至少 30 个正日期、90 个可信负日期、1,000 个正网格日；每项核心任务至少 10,000 个特征完整且标签可信的网格日。SIM-V1 应给出同样统计，但名称必须是“仿真样本量”，不能冒充真实样本量。

## 14. 实施顺序与完成标准

### M0：契约和边界冻结

完成湖界、1 km 网格、时区、字段字典、标签阈值、七任务和五时效定义。完成标准：所有 schema 测试通过，`grid_version` 和 `contract_version` 冻结。

### M1：现有 19 类数据全面映射

把清洗发布包所有来源写入 `source_registry`，明确 observed/derived/proxy/forecast/metadata/rejected。修复水文乱码码值和 pH 单位异常。完成标准：每个原始文件都有唯一终态和去向。

### M2：小范围生成器 MVP

选择一个湖区和一个完整年度，完成气象、水温、水文、营养盐、藻类、空间迁移和观测模拟。完成标准：同一种子逐行哈希一致，基本物理范围和季节性检查通过。

### M3：全湖五年以上逐日仿真

扩展到正式全湖网格，生成基线、富营养化、热浪静风、暴雨入湖等情景。完成标准：日期连续、空间连贯、无非物理值、SIM-V1 全部文件齐全。

### M4：七任务与五时效

生成 T1–T7、T+1/+3/+7/+15/+30 样本，完成三态标签、面积和几何、风险阈值。完成标准：覆盖矩阵无空项，样本数和有效标签统计通过。

### M5：算法接入

实现成员 C 适配器，先验证现有机理/融合框架，再替换占位 AI 为正式模型。完成标准：训练脚本只读取标准发布包，输出携带 dataset/version/track。

### M6：混合训练和真实评估

真实标签到位后，仿真预训练/增强只用于 train，validation/test 只用冻结真实观测。完成标准：真实效果、仿真效果、代理效果三套指标分开展示。

## 15. 测试设计

- 单元测试：公式、单位、阈值、面积、时间连接、标签状态；
- 属性测试：非负性、范围、日期连续、同种子确定性、不同种子差异性；
- 物理不变量：水量/营养状态合理、藻量增长率和水温变化率受限；
- 统计测试：月度分布、极值、相关系数、ACF、持续时间和空间 Moran’s I；
- 泄漏测试：每列的最大 available_time、跨 split 父记录、测试哈希；
- 观测测试：云遮/缺测不成为负样本，接口失败不触发伪观测；
- 回放测试：指定版本、配置、输入哈希和种子可重建相同输出；
- 算法测试：七任务/五时效均能被适配器读取，缺标签时明确失败；
- 压力测试：热浪、静风、暴雨、断网、长缺测、高负荷和极端水位。

## 16. 最终需求覆盖判断

| 需求组 | 本设计覆盖方式 | 当前可达状态 |
|---|---|---|
| 连续五年逐日 1 km 网格 | 机理随机模拟 + 固定网格 | SIM 可完成；REAL 需补观测 |
| 七类任务 | 潜在真值、观测层和统一标签器 | SIM 全覆盖；REAL 标签不足 |
| 五个预测时效 | issue/target/horizon 样本装配 | 可实现 |
| 水华面积与几何 | 有效水面积 × 覆盖率，投影计算 | 可实现，禁止 JPG 面积 |
| 正/负/unknown | 观测证据与覆盖状态控制 | 可实现 |
| 水质/气象/水文/遥感/机理 | 19 类现有数据角色映射 + 生成模块 | 全部纳入，不等价为真值 |
| 70/15/15 + 30 日间隔 | 先切分、后拟合生成器 | 可实现 |
| 防未来泄漏 | available_time/issue_time 契约 | 可实现 |
| 质量、血缘、哈希、复跑 | 发布目录与强制字段 | 可实现 |
| 正式真实效果证明 | REAL-V1 独立真实测试 | 当前不能；需补真实标签 |

## 17. 具体决策

1. **可以做，而且值得做。** 它能让算法完整运作、统一接口、形成可复跑实验，并比第三方简单随机生成更贴近太湖的季节、空间和变量关系。
2. **不能只在对方生成结果上“加一点我们的数据”。** 正确方法是用我方训练期数据估计生成器参数，再从统一潜在状态生成全套互相关联的数据。
3. **实时接口与生成器必须隔离。** 接口数据永远是观测候选；生成器输出永远是 simulated；接口故障不能触发“伪真实补值”。
4. **月度数据可以校准，不能成为逐日真实标签。** 可用于季节曲线、分布、相关性和边界；逐日状态由机理随机过程生成并明确标成仿真。
5. **算法训练采用两阶段最稳妥。** 先用 SIM/HYBRID 做预训练、调试与稳健性训练，再用真实训练数据微调；最终评价只认冻结的真实测试集。
6. **先完成数据工厂，不先重写前后端或算法。** 第一工程目标是输出标准训练包和质量报告；算法只通过适配器消费数据。

这套设计完整覆盖附件规定的七任务、五时效、逐日网格、字段、面积、三态标签、切分、泄漏、血缘、质量、目录、21 项检查和 12 项否决条件，同时把当前工程的全部数据类别和成员 C 算法输入纳入同一条可实现链路。唯一不能通过“生成”解决的是严格真实效果证据：那部分必须等待可审计的连续真实标签。
